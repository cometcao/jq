# 券商收紧大 QMT（禁策略读文件 + 禁策略 HTTP）后的通道方案 v2

> 背景：2026-10 收到券商通知，**约一周后**开始限制大 QMT 的**文件读写**与**网络 HTTP 信号**。
> 现有系统（`qmt_stdqmt_target.py` 外部进程 → `qmt_exchange/rebalance_*.json` → `qmt_rebalance_executor.py` QMT 内置策略）的**唯一跨进程通道就是文件**，文件被禁 = 主线断。
> v2 新增：**官方手册实证**（`config\help\systemfunction\迅投QMT极速策略交易系统说明文档.pdf`，472 页；中文按字形 ID 存储，用 `qmt_manual_extract.py` 还原）。页码均为该 PDF 的页序。

---

## 0. 结论速览：通道优先级

| 优先级 | 通道 | 自动化 | 依赖 | 碰策略沙箱 | 保留你的资金算法 |
|---|---|---|---|---|---|
| **① 主方案** | **便捷交易（文件单）/ 批量预埋单** + 数据导出 | **全自动** | QMT 客户端服务 | ❌ 不碰 | ✅ 算法搬进外部进程 |
| **② 兜底** | 组合交易 + 篮子自动导入 + 人工点「调仓」 | 半自动（~15 秒/天） | 客户端 GUI | ❌ 不碰 | ⚠️ 变成「填交易总量」 |
| **③ 备选** | QMT 内置策略 + 自定义板块读名单 | 全自动 | 策略沙箱内允许读板块 API | ✅ 碰（须零文件 IO） | ✅ 原样 |
| ④ 终局 | 选股整体搬进 QMT 自算 | 全自动 | 策略沙箱内允许行情/财务 API | ✅ 碰 | ✅ 但 AI 过滤做不了 |
| ⑤ 换平台 | PTrade / 换券商 / 报备放宽 | — | — | — | — |

**核心判断**：① 和 ② 用的都是**客户端自身的服务/面板**（`open()` 是客户端调的，不是策略沙箱里调的），
所以「限制策略读文件」这一条**打不到它们**——除非券商通知的范围是「整个客户端禁止外部文件通讯」，这一点必须问清楚（见 §5）。

## 2. 关键事实：官方手册实证

### 2.1 组合交易（篮子交易）——p.176–186
- **篮子管理**（p.176–177）：左栏分类（股票/期货/沪港通…）可**新增、导入、删除**；右栏字段 `代码、名称、数量、相对权重、绝对权重、昨收、涨停、跌停、方向`，可**导入/导出/删除**。
- **导入格式**（p.177）：「合法篮子导入格式为迅投默认格式，在 excel 表格中新建篮子时…保存为 **.csv**」→ 本机 `config\help\baskethelp\*.csv` 就是这 6 个模板。
- **等权分配**（p.179）：买入/卖出方式四种 —— 按组合股票数量 / **按组合股票权重** / 按可用资金 / 按总资产比例。
  权重公式：`分配量 = 总金额 × (某支股票相对权重 / 相对权重合计) / 最新价`
  → **每支股票填相同相对权重 = 等权 = 你要的「平均分配」**。
- **内置股票池**（p.179）：「系统默认支持**账户可用持仓篮子**和**账户持仓篮子**」→ 可把账号持仓直接变成下单板内容。
- **下单面板过滤**（p.185）：`过滤停盘股 / 过滤涨停股 / 过滤跌停股 / 过滤非股票` —— 涨跌停判断是内置的。
- **补单**（p.286）：委托「未成交/部成」任务撤单后可**补单**。

### 2.2 一键调仓（客户端自己算轧差）——p.183–185
> 「调仓是指…将手中股票的现有持仓调整到目标持仓」；面板左侧列账号→点账号显示**当前持仓**；右侧**目标持仓**选择**已创建的目标篮子**→设**交易总量**→确定→「下单面板中显示调仓的股票代码并**自动计算其交易类型**」→下单即「卖出当前持仓中的股票，买入目标持仓的股票」。
> 限制：「调仓中只有**按股票数量**和**按股票权重**两种方式可选」。

**但**：我把 p.176–190 全部含「任务/定时/自动/间隔」的句子都捞了一遍，**调仓没有任何定时/自动触发**，
且全书 `篮子任务` 0 命中 → **② 路线必须人工点一次**（选账号 → 选目标篮子 → 交易总量 → 确定 → 下单）。

### 2.3 篮子自动导入（外部丢 CSV，客户端自己收）——p.364 设置项 17
> 「勾选篮子自动导入并选择路径后，组合交易中的篮子管理内**自动导入一栏会将文件夹里的篮子自动导入**（股票和期货篮子都支持，**仅支持 CSV 文件**）。当勾选『自动用最新篮子填充组合交易』，下单面板中选择篮子选项会自动填入最新的篮子。**目前自动导入的频率是 N 秒**。」

→ 外部进程只需写 CSV 到该文件夹，**篮子自动进 QMT，零人工、零策略**。工具：`qmt_basket_bridge.py`。

### 2.4 便捷交易（文件单）——p.290–292、323–327
> 「便捷交易是 QMT 端**对外提供的下单服务**…外部程序和下单服务通过该协议文件进行通讯」
> 「扫单时，系统**每 N 毫秒就自动扫描文件路径下是否有这个文件**，若有就读取里面的内容，然后**删除该源文件**」
> 协议：`下单类型，通道号，交易市场，交易代码，交易数量，报价类型，交易价格、投资备注（选填）`，半角逗号，`.txt/.csv`
> 撤单协议：`cancel_order 市场代码 合同编号 [市场代码 合同编号 ...]`
> 「用户可添加的便捷交易数量可在**券商管理端-用户管理-设置-便捷交易**中进行调整」← **受券商授权控制，必须确认**

参数编码见 §8 速查表。

### 2.5 批量预埋单 / CSV预埋单（DBF 双向共享文件）——p.327–333
> 「支持外部系统和交易终端之间通过**共享文件**的方式实现数据实时交互：①外部系统写入委托参数；②终端实时扫描监控目录自动委托下单；③**通过主推的方式将委托、成交回报更新到共享文件中**；④**外部系统实时读取共享文件**，根据回报进行后续委托、撤单任务的下发。」
> 「启动监控前，需设置共享文件路径，**路径精确到需监控的 .dbf 文件所在的文件夹**」「下单文件的**文件名不做限制**」
> 下单后生成 `*_result.dbf`，字段：`ORDERID（多个用@分隔）, MESSAGE, STATUS, STRATEGY, NOTE, MARKET, ORDERSYSID`

下单文件字段（**顺序固定**，p.329–331）：
`order_type, price_type, mode_price, stock_code, volume, account_id, acc_type, brokertype, strategy, note`
- `stock_code` 格式 = **市场+代码**（如 `SH600000`）
- `price_type`：`1` 最新价 / `3` 指定价 / `6` 盘后定价 / `M1..M7` 沪深市价类
- `acc_type`：`49` 资金账号；`brokertype`：`2` 股票 / `3` 信用
- 撤单文件字段：`cancel_order|cancel, 资金账号, 委托合同编号, 市场, 空, 空, 空, brokertype`

→ **这是唯一带原生回报回路的通道**，比 2.4 更适合做全自动闭环。

### 2.6 数据导出（持仓/资金的回报回路）——p.337–338
> 「使用数据导出功能，可**定时导出**系统中的资产、持仓、委托和成交等数据…可设置保存路径与导出内容…导出格式可设为 **DBF/TXT/CSV**…委托和成交为增量更新（TXT/CSV 追加，DBF 更新某条状态）…默认导出间隔 1ms」

→ 外部进程由此**无需 xtquant 就能读到真实持仓/资金**，这是 ① 路线能自己算差额的前提。

### 2.7 顺带发现（以后可能用得上）
- p.363 设置项 11：「**函数交易无下单权限时生成篮子**：使用函数交易下单、管理端未开启函数交易下单权限时，所下的单会**自动生成篮子保存在本地**」
- p.363 设置项 12：「**启用文件单备份**：便捷交易执行过的文件将备份到指定路径」
- p.364 设置项 18：「自动用最新篮子填充组合交易」
- `mpython\pythonbalance.py` 是自带「配平」脚本，但**走 miniQMT（XtQuantTrader + userdata_mini）**，miniQMT 已取消 → 不可用（这也是为什么不能指望"自带调仓脚本"）。

## 3. 三条路线怎么选

### ① 便捷交易 / 批量预埋单（推荐主方案）
```
外部进程（有网、有文件权限）
  ├─ 邮件 + AI 过滤 → 目标名单
  ├─ 读 QMT「数据导出」的持仓/资金  ← 回报回路（无 xtquant）
  ├─ 腾讯/新浪行情 → 现价、涨跌停
  ├─ 等权目标 + 差额（原 executor 算法整体搬过来）
  └─ 写便捷交易 .txt 和/或 预埋单 .dbf → 客户端自动扫单下单
QMT 客户端：只做「扫单下单 + 定时数据导出」——**策略彻底不要了**
```
- 优点：全自动、不碰策略沙箱、资金算法原样保留、原生回报回路。
- 风险：便捷交易实例数受**券商管理端授权**控制；预埋单的 DBF 字段长度需首次实盘校准（手册只给了字段名/顺序/类型）。

### ② 组合交易 + 一键调仓（零代码兜底，强烈建议同时配好）
```
外部进程 → qmt_basket_bridge.py 写等权篮子 CSV → 自动导入目录 → 客户端自动收进篮子
人工（~15 秒/天）：组合交易 → 一键买卖 → 调仓 → 选账号 → 选目标篮子 → 按股票权重 → 交易总量 → 确定 → 下单
客户端：自动算轧差 + 自动判断买卖方向 + 内置涨跌停过滤 + 算法下单
```
- 优点：**完全不碰策略、不碰文件单、纯 GUI 官方功能**，合规性最好；零代码改动（只需写 CSV）。
- 缺点：必须人工触发；`cash_reserve_ratio` 那种精度会退化成「填交易总量」。
- 恢复单策略模式下这条最顺：一个账号、一个篮子、一次调仓。

### ③ QMT 内置策略 + 自定义板块（备选，见 §4 工具）
策略侧改成**零文件 IO、零网络**：配置内联，名单走 `get_stock_list_in_sector()`，状态用券商持仓，日志用 `print`。
前提是策略沙箱仍允许板块 API 与交易 API。

## 4. 本仓库现有工具

| 文件 | 用途 | 关键用法 |
|---|---|---|
| `qmt_fileorder_bridge.py` | **① 主方案**：读数据导出 → 取行情 → 等权差额 → 生成便捷交易 txt / 预埋单 dbf；`--feedback` 读回报 | `--inspect` → `--pool x.json`（空跑） → `--execute` |
| `qmt_basket_bridge.py` | **② 兜底**：名单 → 迅投默认格式等权篮子 CSV → 自动导入目录 | `--templates`、`--pool x.json --dir <自动导入目录> --execute` |
| `qmt_manual_extract.py` | 还原官方手册文本（中文是字形 ID 编码，普通工具抽不出） | `--toc`、`--search 便捷交易`、`--page 329`、`--dump qmt_manual.txt` |
| `qmt_channel_probe.py` | 策略沙箱能力矩阵（在 QMT 面板里跑，不下单） | `--safe` 完全不发出站流量；改 `WATCH_SECTOR_NAME` 测板块热重载 |
| `qmt_sector_bridge.py` | ③ 备选：写 QMT 自定义板块（策略用板块 API 读） | `--list`、`--write 我的自选 --from-json x.json` |

- `qmt_fileorder_bridge.py` 用仿造的「数据导出」文件跑通全链路：解析持仓/资产 → 实时行情（腾讯 `qt.gtimg.cn`）→ 等权差额 8 笔委托 → 生成 txt/dbf，格式与手册一致（txt 8 字段；dbf 字段顺序 `order_type…note`，`stock_code=SH600000`）。
- `qmt_basket_bridge.py --templates` 可打印 6 个官方篮子模板原文。

### 5.1 必须问客户经理的一句话
> 「这次限制是针对**策略（模型）**读写文件和访问外网，还是也包含客户端的**便捷交易/文件单**、**批量预埋单**、**篮子自动导入**？便捷交易的下单服务实例数还能开吗？数据导出还能用吗？」

这一句决定 ① 是否可用。若便捷交易/预埋单被一并关闭 → 直接走 ②（GUI 兜底，几乎关不掉）。

### 5.2 GUI 5 分钟验证清单
1. 交易 → 组合交易：确认有「篮子管理 / 导入篮子 / 一键买卖 / 调仓」按钮
2. 设置里搜「篮子自动导入」：勾选 + 指定文件夹 → 丢一个 CSV 进去 → 看是否自动出现在「自动导入」栏
3. 设置里搜「便捷交易」：能否**增加/启动**下单服务、通道号是多少（`0` = 万能通道号）、账号组、文件路径
4. 设置里搜「批量预埋单」：监控路径、生成的 `*_result.dbf` 是否出现
5. 设置里搜「数据导出」：保存路径、导出内容与格式、是否可定时
6. 组合交易 → 一键买卖 → 调仓：走一遍，确认「自动计算交易类型」符合预期

## 6. 尚未验证 / 风险

| 项 | 状态 | 说明 |
|---|---|---|
| 便捷交易实例数 | ⚠️ 待确认 | 手册：可在**券商管理端**调整 → 国金可能未开放 |

| 协议文件编码 | ⚠️ 待确认 | 本工具默认 **ASCII 备注**（`note_language: "ascii"`）规避编码歧义；需要中文备注时用 `note_language: "cn"` 并确认客户端按 GBK 读 |
| 数据导出列名 | ⚠️ 待校准 | 工具用 `COL_*` 别名表启发式匹配，`--inspect` 会打印实际列名，对不上就改别名表 |

| 券商限制的**范围** | ❗关键 | 「只限策略」还是「限整个客户端的外部文件通讯」——决定 ① 能否用 |
| 节假日判断 | 已知限制 | 与旧系统一致（仅工作日） |

## 7. 明确不推荐做的事

用 `ctypes` / `os.open` / `winreg` / 命名管道 / loopback 隧道去绕策略沙箱；或让策略往外部发 HTTP「信号」。
这次是**券商正式通知的合规约束**（配合程序化交易监管），绕过 = 规避监控。
`qmt_channel_probe.py` 里保留这些探测项只是为了**判断限制层次**，不是给你绕。
① / ② 两条路都是在**券商自己提供的正式功能**里做，合规上干净得多。

# 选股信号接入契约（邮件 API v1）

**用途**：你的策略每天把"今天要买/要持有"的股票名单，用**一封邮件**发给我们，
我们的交易系统会按名单自动调仓。

**要点**：你只需要给出**一份有序的股票代码列表**；时间、权重、仓位数量、风控全部由我方负责。
你不需要了解我们的账户、资金量或下单细节。

| 附件 | **恰好 1 个**附件，文件名固定为 **`ttc2_stocks.json`** |

## 2. 附件内容契约

### 2.1 最简（推荐）

一个 JSON 数组，元素是股票代码字符串，**顺序 = 你的排名（越靠前越优先）**：

```json
["600519.XSHG", "000858.XSHE", "300750.XSHE", "601318.XSHG"]
```

### 2.2 也可以（带包装）

```json
{
  "stocks": ["600519.XSHG", "000858.XSHE", "300750.XSHE"]
}
```

除 `stocks` 以外的字段我方会忽略（可以写你自己的 `generated_at`、`note` 等，便于你自查）。

### 2.3 代码格式（严格）

- 6 位数字 + `.` + 市场后缀：`600519.XSHG`（上交所）、`000858.XSHE`（深交所）
- 大写优先；小写、`.SH`/`.SS`/`.SZ` 这类旧写法我方**会自动兼容转换**，但请尽量按上面的标准写
- 6 位数字必须是**真实存在的 A 股代码**
- 不要带空格、不要带股票名称、不要 `sh600519` 这种前缀写法

### 2.4 数量

| 项目 | 建议 |
|---|---|
| 最少 | 我方 `candidate_pool_size`（当前 **13**）只，否则会出现空仓 |
| 建议 | **13 ~ 20** 只 |
| 上限 | 无硬限制，但超过 40 只我方会视为异常名单并**整轮拒单**（安全闸门） |
| 重复代码 | 自动去重（保留第一次出现的位置） |

### 2.5 空数组的语义（重要）

`[]` 表示**清仓信号**（我方会把该策略的持仓全部卖出）。
**如果你今天"没有信号/不交易"，请什么都不要发**（而不是发空数组）。
不发邮件 → 我方当天不会生成新名单 → 该策略当天不交易，持仓保持不动。

## 3. 我方会怎么用你的名单

1. **合规过滤**：默认会过一遍我们的 12 条规则（退市风险、ST、财务造假、立案调查、审计否定、
   资金占用等），**保持你的原始顺序**；**本策略已配置为跳过该过滤**（`ai_filter: false`），
   即：**你发什么就按什么下单**，所以合规风险由你的策略负责。
2. **等权建仓**：名单前 N 只（当前 `max_holdings = 6`）为目标持仓，按总资产等权分配；
   第 N+1 名之后属于"替补/监控池"，用来在目标票涨停/停牌时**补位**。
3. **卖出规则**：不在名单里的持仓会被卖出（停牌/涨停/跌停的极端情况按交易所规则处理）。
4. **ST 股**：我方**不买**（下单层硬拒），请你事先剔除。
5. 你的名单**不需要**考虑我们有多少钱、买多少股。

## 4. 数据校验规则（我方按此判定你的文件是否可用）

| 校验 | 不通过时的行为 |
|---|---|
| 文件是合法 JSON 数组（或含 `stocks` 数组的对象） | 视为名单无效 → 当天不交易（不生成新执行文件） |
| 至少 1 个有效代码 | 同上 |
| 单个条目必须是 `6位数字 + 合法后缀` | 该条目被丢弃并记录告警；其余正常使用 |
| 附件必须是**当天**收到的（文件写入日期 = 今天） | 视为"今天没有新信号" → 当天不交易（**不会**拿昨天的名单顶替） |
| 14 天内更新过 | 超过 14 天视为过期 → 清仓 |

## 5. 自检（建议你每天发信前跑一次）

```python
# check_list.py —— 只用标准库，直接 python check_list.py 名单.json
import json, re, sys

PATTERN = re.compile(r"^\d{6}\.(XSHG|XSHE|SH|SS|SZ)$")
MIN_NAMES, MAX_NAMES = 13, 40

raw = json.load(open(sys.argv[1], encoding="utf-8"))
codes = raw.get("stocks") if isinstance(raw, dict) else raw
assert isinstance(codes, list), "顶层必须是数组，或含 stocks 数组的对象"

seen, ok, bad = set(), [], []
for c in codes:
    c = str(c).strip().upper()
    if not PATTERN.match(c):
        bad.append(c)
        continue
    if c[:6] in seen:
        continue
    seen.add(c[:6])
    ok.append(c)

print("有效:", len(ok), "重复已去掉:", len(codes) - len(ok) - len(bad), "非法:", len(bad))
if bad:
    print("非法条目:", bad[:10])
if not (MIN_NAMES <= len(ok) <= MAX_NAMES):
    print("警告: 数量 %d 不在建议区间 %d~%d" % (len(ok), MIN_NAMES, MAX_NAMES))
if not ok:
    print("错误: 没有有效代码，我方会视为无效名单")
sys.exit(0 if ok and not bad else 1)
```

## 6. 时间线（北京时间，交易日）

```
09:15   建议你这之前把邮件发出（留足余量）
09:25   我方最晚这个时刻拉取邮箱，保存附件 → 校验 → 生成执行文件
        └─ 此后到达的邮件当天不使用
09:30   上传到交易服务器（客户端定时上传）
09:35   开盘后第一轮调仓（先卖后买）
```

> 具体拉信时刻 = 我方下单时刻前 10 分钟（当前 09:25）。**你只要保证 09:15 前发出就行**，
> 我方若调整时刻会提前通知你。

- **09:25 之后到的邮件，当天不使用**（我方不做补跑：刻意设计，避免用旧信号追高）。
- 若某天 09:25 前没收到你的邮件，当天该策略**不交易**（持仓不动），也不会报错停运。

### 6.1 一天可能要调仓两次

我方支持一个策略**一天最多两个调仓时点**（都在开盘后，例如 09:35 与 10:00），
但**你每天只需要发一封邮件**（一份名单）：

| 你发的内容 | 我方行为 |
|---|---|
| 每天 1 封（推荐） | 两个时点都用同一份名单：第一个时点完成建仓，第二个时点只处理"第一个时点没成交/买不到"的残余（例如涨停被跳过、卖单部分成交） |
| 一天内发第 2 封（同一主题） | 以**最新一封**为准；第二个时点会按新名单调整（产生差额委托） |

> 所以：**你不需要为了"两次调仓"发两封信**。名单没变就不用重发。

## 7. 变更约定

- **新增字段**：你可以在 JSON 里自由增加字段（`generated_at`、`note` 等），我方会忽略，不影响对接。
- **改文件名 / 改主题关键字**：必须提前一天告知，我方需要改配置并重启进程。
- **改了代码格式**（例如改成 `sh600519` 前缀写法）：我方会判定为非法条目并丢弃 → 等于当天没信号。
- **停发/长期不做**：提前说一声，我方把该策略的持仓清掉并停用（避免你的名单过期后被清仓时点错）。

## 十一、系统分层架构与执行约定

数据处理与呈现层（Plugin + run_python）：清洗、统计、图表与表格渲染，以及附录 D 的渲染前校验。不做金融判断或价格结构解读。

事实提取与测量层：指标取数、锚校验、比价计算。只返回结构化事实与对比结果。

事件情景层：事件日历整理（事件面输入）+ 事件分支枚举（事件面输出）；禁止项见 F08。日历更新时整个日历与全部分支一起重新生成（保留快照，见第八节）。

流程编排层：Markdown 指令（Skill），规定触发条件、调用顺序、输出格式，见第十四节。

平台不承担：价格结构判断、走势分析、K 线印证、买卖决策、策略信号生成、价格序列形状的图呈现（F02、F03）。

### 执行约定（新增）

接手指令时按以下顺序执行，不得跳步：

1. **查可得性**：按附录 C 核对本次请求涉及的指标在当前环境的取数路径与授权状态；某环判为 G3 且无替代时，先如实告知，再给可替代项。
2. **判层与指标**：确定 layer 与 indicator_id，并按六环确定 `channel` 与 `subject`；未注册的指标先走事实注册规则，不得临时造字段。
3. **取数并落统一字段**：第四节字段齐全；缺失与过期如实标注（missing_type / stale）。
4. **锚校验后比价**：七锚（含归属锚）+ operand_order + universe + reference + comparable_from 全部通过才计算；输入必须指向已落地事实记录，不得指向 `prev_value`、假设值或分支结果（事实域封闭，ADR-022）；不通过则不出结果并说明原因（F06）。
5. **渲染前校验**：执行附录 D 的 V-清单；任一失败则拒绝输出该区块，不得"先输出再提醒"。
6. **按第九节六段模板输出**，末尾附固定尾句与元信息段。

**数据缺失时的对话规则：** 如实报缺失与替代项，不猜、不用非同质指标凑数、不静默省略该区块；缺失项集中列在元信息段（第 ⑤ 段）。

**歧义时的对话规则：** 标的、窗口、口径、层级任一不明确（如"半导体"对应多只 ETF、"最近"未给窗口），先提一个具体问题再执行，不得自行选定后附带说明。

**草案条款：** 输出若依赖 draft 条款，元信息段必须写明 `rule_status=draft`，并列出所依据条款编号（附录 E）。

## 十二、载体形态与环境适配层

### 12.1 载体形态

平台默认载体：**AI agent + Skill 对话式面板**。输入为自然语言指令 + 标的参数，输出为对话内图表、表格、结构化摘要。Skill 体系见第十四节。

当前实施环境：DSH（DeepSeek Harness）+ Skill + 本地脚本（插件路线已放弃，见 ADR-039）。此处 "Plugin" 特指数据处理与呈现层的实现载体（如 DSH 插件），与第十一节用法一致；在 DSH 生态中"Plugin"泛指一切扩展包，勿混淆。框架不绑定此环境，更换环境时只重写适配清单（见 12.2）。

**三类内容的边界（统一表述）：**

- **框架核心（与运行环境无关，更换环境不改）：** 第一至十节、第十四节、第十八节。
- **口径附件（随口径版本更新）：** 附录 A、附录 B、附录 F。
- **实现层（随环境替换）：** 第十一、十二、十三、十五、十六、十七节与附录 C、附录 D、附录 E。

后续可选演化方向（当前不实施）：独立 Web 应用（需另行设计数据存储、调度、前端）、定期报告推送。载体演化不改变框架核心。

### 12.2 环境适配层

框架核心与口径附件与运行环境无关。每个目标环境单独维护一份《环境适配清单》，包含 5 项：

1. **可用工具清单：** 该环境可调用的数据源工具、计算环境、可视化组件，逐一标注实际可调用的数据范围与限制。
2. **渲染契约：** 图表/表格组件接受的 schema 与已知限制（含 V1/V2 判据在本环境的落地方式）。
3. **数据源映射：** 第六、十节中每个 A/B 类源在该环境的具体获取路径（API、插件、人工上传）。当前环境见附录 C。
4. **存储方案：** 见下 12.3。
5. **调度方案：** 事件日历"每日检查更新"的触发方式（人工触发/定时任务）与失败告警方式。

环境适配清单在第零阶段编写并验证，验证通过前不进入第一阶段。更换运行环境时，只重写适配清单，不改框架核心与口径附件。

## 十三、测量工具接入规范

> 第 1、2 节原为 D08/D09 重建稿，**V2.45.1 定稿**（以 `skills/bijia-measure.md`、`skills/fundamental-facts-market.md` 为准）；第 3、4 节为 V2.3 原文（仅"技术面"改为"事件面"）。

### 1. 事实提取工具（D08，V2.45.1 定稿）

输入：layer、channel（C1–C6 或"背景"）、subject（政策/公共池/外部/机构/散户/产业资本）、指标注册 ID 或子类名、观测时点、窗口参数。输出：符合第五节 schema 的结构化记录，含第四节全部统一字段，并显式带 `channel`、`subject`、`proves`、`does_not_prove`。

规则：

- 只返回事实，不做任何对比、判断、解读。
- 取数失败时如实填 missing_type，不得返回估算值冒充观测值；使用替代指标时必须 fallback_flag=true 并写明 fallback_path。
- 政策状态类事实必须含 effective_since、status_enum 与 supersedes。
- 原始序列类事实只返回元数据 + raw_series，不渲染；value_kind 必须为 price。

### 2. 比价测量工具（D09，V2.45.1 定稿）

输入：两个（或一组）事实记录或已存在的 compare_id、compare_type（time_self/cross_sectional）、compare_operation（ratio/difference/spread/percent_change）、operand_order、result_form（point_value/percentile/rank）、universe（rank 必填）、reference（偏离度必填）、anchor 声明、window。输出：附录 B 的比价输出 schema。

规则：

- 计算前校验七锚：同质锚（attribute 与 transform 均相同）、属性锚、口径锚、窗口锚、层级锚、归属锚（跨层时须有归属来源与版本）、量纲锚；任一锚不满足则拒绝计算并说明原因，不输出"勉强可比"的结果（F06）。同质锚与属性锚按注册表判定，不靠模型语义裁量。
- 输入必须是已落地的事实记录或既有 compare_id（事实域封闭，ADR-022）；不得引用事件分支的 `prev_value`、假设值或分支结果。
- 分位数基于 window 内的历史分布计算，窗口不足或窗口起点早于 comparable_from 时拒绝计算并填 caliber_mismatch。
- 输出中不含输入方原始数值序列（仅 current_state 元数据与 inputs 的 ID），不含任何评价性措辞。
- 渲染前必须按第七节 V1/V2 判据判定该 series 是否可画；不可画则只输出数值表并说明原因。

### 3. 事件日历工具（归事件面输入层）

输入时间窗口（默认 30 天，可配置 window_days）、层级、标的范围；输出未来事件日历。仅"未来预定"状态的事件进入默认呈现；取消事件状态流转为"已取消"并保留记录；确定性标准为官方公告或官方日历明确列出，官方源优先；每日检查一次更新，有新公告时事件驱动更新。manual 录入必须带官方链接（8.1）。禁止输出事件结果预测、一致预期数据、受影响指标标注。

### 4. 事件分支工具（归事件面输出层）

输入事件日历；输出事件分支 schema。affected_indicators 必须是注册表中的 indicator_id；prev_value 按 8.2 的前值来源规则获取。禁止输出概率、排序可能性、方向判断、价格层面印证标志、历史事件统计拟合、一致预期数据。持平判定按 8.2，前值不可得时置 branch_ordering_applicable=false。

### 5. 工具与 Skill 接口摘要（V2.45.1）

> 本节由原 `skills/` 的 8 份一页规格合并而来，只保留**别处没有**的内容：**输入参数、失败态、产物位置**。规则本身以第一至十节与附录为准；运行时行为以 `dist/market-state/` 的自包含包为准。本节的用途是：将来写插件时，一眼看到每个工具吃进什么、失败时怎么答、结果落在哪。


#### 5.1 市场层事实（`fundamental-facts-market`）

**输入参数**

| 参数 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| layer | enum | 是 | `market` | 本 Skill 仅市场层 |
| rings | array | 否 | C1–C6 全部 | `C1`…`C6` 的子集 |
| subjects | array | 否 | 全部 | 政策/公共池/外部/机构/散户 |
| as_of | date | 否 | 最新可得 | 最终页首 as-of 仍取最慢环（L5） |
| window | string | 否 | ADR-027 | 仅派生物需要 |

> 参数之间互斥时可只给一部分；**任一层级/标的/窗口歧义必须先问一句**（第十一节执行约定）。

**失败态**

| 情形 | 回应 |
|---|---|
| 某环全部无源 | 保留环名标"不可读"，并列出"缺什么"（不猜、不用近似量顶替） |
| 频率不匹配（月/日混排） | 不平铺；各自标 data_period，页首只放最慢环的 as-of |
| 请求歧义（"最近"未给窗口） | 先问一句，不默认 |
| 指标未注册 | 先走事实注册规则，不临时造字段 |
| 数据 stale 超 3 倍 | 该环写"不可读"，不进状态词、不参与背离计数 |

**产物位置**

事实记录落 `data/facts/<data_period>/`；渲染交 `panel.render`；校验回执随输出折叠。


#### 5.2 板块层事实（`fundamental-facts-sector`）

**输入参数**

| 参数 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| board_id | string | 是 | — | 须绑定 `standard + version + effective_from`（R1）；未绑定则拒绝 |
| rings | array | 否 | C1–C6 全部 | C4 允许缺席（默认不可读） |
| as_of | date | 否 | 最新可得 | 页首 as-of 取最慢环（L5） |
| aggregation | object | 否 | 注册表默认 | 等权/市值加权、剔除规则、覆盖率下限（R2） |

**失败态**

| 情形 | 回应 |
|---|---|
| 无成分表版本 | 拒绝时间自比；只能出截面，并在元信息标"未绑定版本，仅截面" |
| 覆盖率低于下限（如 80%） | 该加总项标 `fallback` 或直接不可读；不得当完整值用 |
| 跨版本历史值 | 拒绝并入序列，标 `caliber_mismatch`（R3），单列"历史参考"并注明版本 |
| C4 无源 | 默认空环，不得用板块成交额或两融代替 |
| 板块 id 歧义（同名不同级） | 先问一句，不猜 |

**产物位置**

`data/facts/sector/<board_id>/<data_period>.json`；相对量与排名引用 `data/compare/<compare_id>.json`。


#### 5.3 比价测量（`bijia-measure`）

**输入参数**

| 参数 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| compare_type | enum | 是 | — | `time_self` / `cross_sectional` |
| inputs | array | 是 | — | 每项 `{ref_type: indicator_id \| compare_id, ref, layer, data_period}`；**必须是已落地事实或既有 compare_id**（事实域封闭，ADR-022） |
| compare_operation | enum | 是 | — | `ratio` / `difference` / `spread` / `percent_change` |
| operand_order | string | 差值/比值类必填 | — | 如 `M2同比 − M1同比`、`板块PE / 全市场PE` |
| result_form | enum | 是 | `point_value` | `point_value` / `percentile` / `rank` |
| universe | string | `rank` 必填 | — | 对照全集与排序方向，如"申万二级 31 个板块" |
| reference | string | 偏离度必填 | — | 窗口均值/中位数/上期值/参考线 |
| window | string | 否 | ADR-027 默认 | 起点不得早于双方 `comparable_from` |
| layer | string | 是 | — | 市场/板块；跨层时须属"细层 ↔ 所属粗层" |

**失败态**

| 情形 | 回应 |
|---|---|
| 锚不符（同质/口径/量纲/层级/归属任一） | 不出结果，说明是哪一锚、为什么不符；不给"勉强可比"的近似值（F06） |
| 口径断点（窗口早于 `comparable_from`） | 填 `caliber_mismatch`，建议改窗口或分段；不得拼接（F11） |
| `rank` 缺 universe / 偏离度缺 reference | 先问一句，不默认补 |
| 输入含假设值或 `prev_value` | 拒绝，指向 ADR-022 |
| 数据缺失 | 不出该比价，写"不可读｜依据：输入缺失｜边界：无法比较" |

**产物位置**

`data/compare/<compare_id>.json`；渲染片段交 `panel.render`；校验回执随输出折叠。


#### 5.4 事件日历（`event-calendar`）

**输入参数**

| 参数 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| window_days | int | 否 | 30 | ≤ 90 |
| layer | enum | 是 | — | 市场 / 板块 / 个股；层级各自独立维护，不跨层关联 |
| scope | string | 否 | 该层全部 | 板块 id 或标的范围 |
| entry_mode | enum | 否 | auto | `auto`（抓取）/ `manual`（人工录入，须带官方链接） |

**失败态**

| 情形 | 回应 |
|---|---|
| 某源不可抓 | 该源条目记 `not_crawlable`，转人工录入流程；不得用媒体日期补位 |
| 无官方链接 | 不入日历；作为线索列在元信息"未确认线索"里 |
| 事件跨层 | 各层独立维护，不合并；同一日期在不同层可出现两条 |
| 与上一版无差异 | 不重生成，`observation_time` 不变（8.1） |
| 状态流转（发生/取消） | 重生成整历并保留上一版快照，`calendar_version` 递增 |

**产物位置**

`data/events/<calendar_version>.json` + 快照目录；指针行由 `full-workflow` 组装时引用。


#### 5.5 事件分支（`event-scenario`）

**输入参数**

| 参数 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| event_id | string / array | 是 | — | 取自 `event-calendar` 的"未来预定"条目 |
| calendar_version | int | 是 | — | 必须与日历版本一致；不一致则先重取 |
| branch_kind | enum | 否 | 按 event_type 推断 | 数据发布 / 会议 / 解禁与指数调整 |
| prev_value | object | 否 | 自动获取 | `{indicator_id, value, data_period, source_link}`；优先随发布获取 |

**失败态**

| 情形 | 回应 |
|---|---|
| 前值不可得 | 置 `branch_ordering_applicable=false`，写"排序不适用：前值不可得"；不得用推测前值 |
| 标志不可机械比对 | 拒绝生成该分支，改为"该事件暂无可机械观测的标志" |
| 事件已发生/已取消 | 不生成分支；提示状态流转 |
| 日历版本不一致 | 拒绝，要求先重取日历 |
| 受影响指标不在注册表 | 先走注册流程，不得临时造 id |

**产物位置**

`data/scenarios/<event_id>-<calendar_version>.json`；与日历快照按版本对齐，不覆盖旧版本。


#### 5.6 市场层层级编排（`macro-layer`）

**输入参数**

| 参数 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| rings | array | 否 | C1–C6 | 六环子集，仍按 C1→C6 输出 |
| include_events | bool | 否 | true | 是否调用事件层与 C1 指针 |
| window | string | 否 | ADR-027 | 只影响比价环节 |
| as_of | date | 否 | 最新可得 | 页首仍取最慢环（L5） |

**失败态**

| 情形 | 回应 |
|---|---|
| 事实层某环全空 | 保留环名标不可读，其余照常；不中止 |
| 比价任务输入缺失 | 跳过该任务并在元信息写明"缺输入"，不降级 |
| 事件源不可抓 | 事件层写"日历不可用（not_crawlable）"，C1 指针写"暂无日程" |
| V 清单不过 | 只拒该区块，回执写条数与原因 |
| 请求歧义 | 先问一句 |

**产物位置**

`reports/market-<as_of>.md` + `reports/market-<as_of>.checks.json`。


#### 5.7 板块层层级编排（`sector-layer`）

**输入参数**

| 参数 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| boards | array | 是 | — | 每个须有 `board_id` + 成分版本（R1） |
| rings | array | 否 | C1–C6 | C4 允许空 |
| include_events | bool | 否 | true | 板块层事件独立维护 |
| universe | string | 否 | 同层板块集 | 排名用；须声明所含板块与各自成分版本 |
| as_of | date | 否 | 最新可得 | 页首取所有标的中最慢的一环 |

**失败态**

| 情形 | 回应 |
|---|---|
| 某板块无成分版本 | 该节只能截面，标"未绑定版本"；不进排名（排名要求可比的 universe） |
| universe 内版本不一致 | 排名保留但标"仅截面参考"；不做时间自比 |
| 覆盖率不足 | 加总项标 fallback/不可读；不进排名 |
| 板块集合为空或全不可读 | 不输出空报告；先问用户补板块或数据源 |
| 请求跨层（市场 + 板块） | 拒绝，交 `full-workflow` 编排（F07） |

**产物位置**

`reports/sector-<as_of>.md` + `reports/sector-<as_of>.checks.json`；各板块引用自身 `data/facts/sector/` 与 `data/compare/`。


#### 5.8 总编排（`full-workflow`）

**输入参数**

| 参数 | 类型 | 必填 | 默认 | 约束 |
|---|---|---|---|---|
| scope | array | 是 | — | `market` / `sector:<board_id>` / 组合；个股层暂不支持 |
| rings | array | 否 | 该层 C1–C6 全部 | 六环子集，仍按 C1→C6 输出 |
| as_of | date | 否 | 最新可得 | 最终页首仍取最慢环（L5） |
| window | string | 否 | ADR-027 | 只影响必比价环节 |
| include_events | bool | 否 | true | 是否附事件层与 C1 指针 |

**失败态**

| 情形 | 回应 |
|---|---|
| 某环全空 | 保留环名标"不可读"，其余环照常输出；不因此中止整份报告 |
| 比价任务不可做（锚不符/缺 universe） | 跳过该比价并在元信息写明原因，不降级成"近似比较" |
| V 清单不过 | 只拒出该区块，其余照常；回执写明条数与原因 |
| 取数超时/端点故障 | 该指标标 `source_unavailable`，继续其余；不静默省略 |
| 请求歧义 | 先问一句，不做默认假设 |

**产物位置**

`reports/<as_of>-<scope>.md`（正文）+ `reports/<as_of>-<scope>.checks.json`（V 清单回执）；事件与比价引用各自的 `data/` 记录编号。

## 十五、输入与输出

输入：自然语言指令 + 标的参数，例如"跑板块层比价测量，半导体 ETF，基准用宽基指数，最近 120 天""今天只看市场层基本面""把未来 30 天的事件日历和分支列出来"。也可上传用户抓取的 CSV/Excel 文件作为补充数据。

**上传数据的三步判定：**

1. **溯源定级**：能给官方一手源链接 → A；能溯源至官方数据的转售 → B；无来源说明 → C 并注明"来源未核验"。
2. **核验状态**：未与官方源逐条核对前，missing_type=pending_verification；核对后填 none。
3. **传闻排除**：上传内容若为传闻、无来源数字或无法核验的推测，**不得作为数值事实录入**，只能作为事件日历线索，且须待官方确认（与第十节 1 的规则一致）。

输出：图表（比价序列折线、事实表格、指标网格等非价格序列形状的内容）、结构化事实摘要、比价对比结果、背离标注（同向 / 存在背离：多数方向 + 反向指标名 / 方向分歧）、未来事件日历、事件情景分支。事件日历可独立输出；事件分支为可选附加层。呈现形态与顺序按第九节六段模板；不呈现价格序列形状的图（F03）。

输出末尾固定附带："以上为客观事实、对比数据与事件分支枚举；价格结构判断与决策请自行完成，事件分支请到 K 线平台印证。"

## 十六、实施原则

串行推进，不并行（F13）。

每个阶段有明确的输入、输出、完成标志；完成标志必须是可复现的验收证据（数值对账结果、渲染截图或链接、校验器日志）。

**最小闭环的定义（明确）：** 一个闭环 = 同一层级的"事实 + 比价 + 事件日历"三段同时可出，且通过附录 D 的 V-清单。仅有事实层或仅有比价层不算闭环。

数据依赖先于功能依赖；阶段计划按"先验数据可得性、后写功能"排。

框架版本与实施阶段解耦。

每阶段结束留存回归样本（输入 → 期望输出），供下一阶段与后续修订回归。

（工作方式提醒）AI 加速的是编码，不是核对与拍板。

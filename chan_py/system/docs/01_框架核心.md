# 01 框架核心 · V2.128.0（变更见 CHANGELOG.md）

> 本文件是《全景客观金融分析工作台》的一部分。节号与附录字母全局连续，文件地图见 `../00_README_文档地图.md`。

## 一、项目目标

构建一个面向股票/金融市场的全景客观数据工作台。系统负责抓取、清洗、归并多源数据，以图表、表格、结构化摘要的形式客观呈现市场、板块、个股三个层级的事实、对比结果与事件情景分支。

系统的输出边界由禁止清单统一定义（F01–F23，见 `03_禁止清单.md`），本节不重抄条文。定位一句话：平台只产出客观事实、比价与事件分支；价格结构判断、走势分析与买卖决策，全部由用户在外部行情软件研读 K 线后自行完成。

平台定位：数据工作台 + 事件情景工作台。

双工具并行是既定使用方式：平台提供基本面事实、比价数据、事件情景分支；价格结构判断在外部行情软件中完成。平台不呈现任何价格序列形状的图（判据见第七节 V1/V2），也不呈现任何价格结构标注；OHLCV 仅在数据层存在，用于产出收益率、排名等比价输入（F04）。

平台精度边界：日线。平台只处理日线及以上级别的数据。30/60 分钟、1 分钟、tick 级、高频资金流全部不在平台范围内（F19）。

平台层级优先级：**v1 只做市场层与板块层**；个股层明确不做（D10 关闭），需要时以板块 ETF 或个股公告数据在板块层内加总，不另立一层。

**载体形态（默认）：AI agent + Skill 对话式面板。** 用户以自然语言触发各层 Skill，输出为对话内图表、表格与结构化摘要。其他候选载体（独立 Web 应用、定期报告推送）为后续演化方向，见第十二节。

## 二、核心认知框架

根源目标：资金。市场沉浮的关键是买卖，其燃料是资金。但资金不可直接观测，只能通过代理变量逼近。单一面必然有盲区，因此需要多个失效条件不同的视角交叉支撑。

两个分析面（平台侧），外加排在最后的第三块：

**基本面 = 一切当下的事实。** 回答"是什么"。包括财务数据、资金数据、情绪数据、宏观数据、现行有效的政策状态、占比类派生指标、相关系数类派生统计量、日线 OHLCV 原始数据（仅在数据层，用于产出比价输入）。

> 市场层的基本面按**六环**排序（ADR-019）：**C1 政策设定 → C2 资金供给 → C3 资金价格 → C4 场内杠杆与资金池 → C5 主体行为（外部/机构/散户）→ C6 市场结果**。六环是资金通道顺序，不是因果断言。板块层按同名同序**重定义**（见本节板块层六环），个股层待定。财务与情绪类事实只存在于个股层。

**比价 = 同一数据不同时间的对比，或同性质数据同一时间的对比。** 回答"相对谁、强还是弱、现在比过去如何"。同性质 = 度量同一个属性，不要求指标名称相同。时间自比：同一数据、同一口径、不同时间点。空间互比：度量同一属性的两个实例、同一时间点。

**事件面 = 对已知会发生的事情枚举可能的结果分支，并给出事件层面的可观测标志。** 回答"已知会发生什么、可能有哪些结果、如何知道发生了哪个结果"。本框架中的"事件面"特指事件驱动推断，与通常意义的价格技术分析无关（V2.3 及之前称"技术面"，V2.4 起更名）。

事件面 = 事件日历（输入）+ 事件分支枚举（输出），两者一体。**呈现顺序上事件面排在基本面与比价之后（第三块）**；但它的输入端与 C1 共用日程——C1 末尾给出"未来 30 天政策与发布日程"的指针，事件层展开完整日历与结果分支（ADR-020）。事件日历是"已确定会发生但尚未发生"的事实——它确定，但对当下没有确定影响，所以归事件面。现行有效的政策状态归事实层（当下事实）；未来预定事件（数据发布日、会议日期、财报披露日、解禁日）归事件面。历史已发布的政策事件不单独记录——政策影响通过现行状态与时间自比体现。

三块是认知链条上的三个环节：基本面提供事实；比价在事实之上做对比；事件面对已知事件做分支枚举。价格结构判断与买卖决策完全由用户在平台外完成。

事件面（事件驱动）与价格结构推断的区别：前者输入是事件，只需枚举可能结果和可观测标志，不需要研读 K 线；后者输入是价格序列，需要主观研读 K 线。平台做前者，不做后者。事件情景分支的用途是：用户带着这些分支到 K 线平台，观察事件落地后价格结构如何反应，两者在自己脑中对照。

各观察角度在呈现层并列陈列。系统按呈现分组做机械的数值变化方向一致性判定（同向/背离，规则见第七节），不做加权、不做综合评分、不把背离强行合成单一信号。事件分支之间也是并列关系，不排序可能性、不给概率、不判断哪个更可能。

三个层级：市场 → 板块 → 个股。观测与呈现的顺序，不是判定链。系统从宏观看到微观，逐层并行陈列，不做任何跨层判定（F07）。事件日历在三个层级各自独立维护，不跨层关联。

**术语映射（供实现使用）：** 两个分析面的呈现层展开——基本面→事实层，比价→对比层；事件面不是第三个面，而是排在两者之后的**第三块（事件情景层）**。三块/三层是同一组概念的两种叫法，实现中字段名一律用 layer 与 face 两套，不混用。**呈现顺序固定为：事实层 → 对比层 → 事件情景层**（事件放最后，但 C1 内有日程指针回流）。

## 三、事实层与比价层的归属判别规则

| 运算类型 | 归属 | value_kind | 例子 |
|---|---|---|---|
| 单一观测值 | 事实层 | level（价格类为 price） | 收盘价 12.5 元、M2 同比 7.2%、融资余额 1.52 万亿 |
| 聚合值（求和/均值/中位数） | 事实层 | level | 全市场成交额、板块平均换手率、行业市值中位数 |
| 原始序列（日线 OHLCV） | 事实层（数据层专有，F04） | price | 宽基指数日线、行业 ETF 日线、个股日线 |
| 派生指标（占比/合成指标） | 事实层 | ratio | 沪深股通成交额占 A 股成交额比例（盘后口径）、居民存款定期化比例、板块成交占比、融资买入额占比、拥挤度（换手率分位、成交额分位等的合成指标） |
| 派生统计量（相关系数） | 事实层 | level（统计量） | 板块内个股相关系数、两序列的 Pearson/Spearman 相关系数 |
| 现行有效政策状态 | 事实层 | qualitative | 当前 LPR 水平、当前存款准备金率、当前行业监管状态、当前外汇政策状态 |
| 未来预定的定性事件 | 事件面（事件日历） | — | 数据发布日、会议日期、财报披露日、解禁日、指数调整生效日 |
| 同质时间自比 | 比价层 | 由算子决定 | CPI 上月 vs 本月；PE 当前 vs 自身历史分位；营收同比；环比 |
| 同质空间互比 | 比价层 | 由算子决定 | 两只股票市值；个股与板块指数；M2 增速与 M1 增速之差；板块涨幅排名；股息率 vs 国债收益率；CNH vs CNY；2Y vs 10Y 国债收益率 |
| 未发生（假设）值与事实的比较 | 不归任何面：只在事件分支中作**定义条件** | — | "公布值 > 前值""高于某客观参考值" |
| 对已知事件枚举可能结果分支 | 事件面（事件分支枚举） | — | 数据发布后的高于前值/低于前值/持平；会议后的有实质性决议/无实质性决议/延期 |
| 对价格序列做结构推断 | 不在平台范围内（F02） | — | 笔、线段、中枢、走势类型、背驰、买卖点 |

**一句话判别：** 问"这是不是一个数"，是 → 事实层；问"相对谁、差多少、排第几、处在什么分位"，是 → 比价层。分位、排名、同比、环比、价差、比值、归一化，一律归比价层；占比归事实层。

容易归错的七类：

1. **同比/环比归比价层。** "营收 50 亿"是事实；"营收同比 +15%"是同一数据不同时间，归比价层。
2. **占比归事实层。** 沪深股通成交额与 A 股成交额是部分/整体，不是同一属性的两个实例。占比的时间分位归比价层。
3. **分位归比价层。** "PE 25 倍"是事实；"PE 处于近 3 年 30% 分位"是同一数据不同时间。**任何以"分位"或"排名"为形态的结果都不是事实记录**（第六节板块层清单、第十节 D 类示例均按本条执行）。
4. **跨资产对比归比价层，前提是度量同一属性。** 股息率与国债收益率都度量"资金收益率"；CNH 与 CNY 都度量"人民币汇率"；2Y 与 10Y 都度量"国债收益率"。
5. **相关系数归事实层。** 相关系数度量的是两个序列的关系，不是任何单一属性的实例。
6. **现行政策状态归事实层，未来预定事件归事件面。** "当前 LPR 为 X%"是事实；"LPR 将于 X 日公布"是事件面的事件日历；对后者的结果分支枚举是事件面的事件分支枚举。历史已发布的政策事件不单独记录——政策变化通过"当前状态 vs 上一期状态"的时间自比体现。
7. **价差归比价层，不归事实层。** 风险溢价（股息率 − 国债收益率）、CNH-CNY 价差、期限利差都属比价层输出，不作为任何一面的"代理指标"直接注册为事实。**例外（ADR-012）：** 某价差数值若由 A/B 类源直接发布（source_published=true，如中债发布的信用利差），可作为事实登记；判据是"谁发布的数值"，不是数值长什么样。

非同质跨资产对比单独列出。指数与商品的比值、人民币汇率与美元指数的对比、股票与房地产的比价——这些对比双方度量的是不同属性，不满足同质锚。它们不作为标准比价结论，只在"跨资产并列（非同质，仅参考）"区块中呈现。

**事实域封闭（ADR-022）：** 比价的输入只能是**已落地的两方事实记录**（或既有的 compare_id）。三类东西永远不进入比价：① 未发生的假设值；② 事件分支里的结果标签；③ 由假设推出的"如果…则…"数值。事件分支中的"公布值 > 前值"是**分支的定义条件**，不是一次事实对比——它不生成 compare 记录、不进入比价层，`prev_value` 只作为定义分支的参照点。理由：锚点校验的七个锚（口径、窗口、层级、归属、同质、属性、量纲）全都建立在"两方都已是事实"之上，输入一混入假设值，锚立刻失效。

**指标归属唯一性（新增）：** 每个 indicator_id 只有一个 layer（市场/板块/个股）。同一指标若同时出现在两层清单中，以更细层为注册层，粗层只引用同一 indicator_id，不重复注册、不另起记录。此规则解决第六节内部结构与板块层清单的重叠。

**跨层比价的边界（ADR-013）：** 上表中"个股与板块指数"这类跨层比价**允许**，但只允许"细层 ↔ 其所属粗层"——个股 ↔ 其所属板块、板块 ↔ 全市场或其所属指数；并须声明归属来源与版本（板块成分表、行业分类标准）。无归属关系的跨层对比（如"半导体 ETF vs 银行个股"）不成立，按非同质处理，只能进入"跨资产并列（非同质，仅参考）"。该约束在第七节实现为**归属锚**。

呈现时的关系：两层各出现一次，不重复。事实层是"原料表"，比价层是"对比表"，通过 indicator_id 关联。原始序列类型的事实（OHLCV）不进入呈现层（F04）。

所有事实记录、比价记录、事件日历与事件分支**统一包含**下表字段（各节 schema 列出的是本节特有字段，下表字段不再重复抄写，但必须存在）：

| 字段 | 含义与取值 | 必填性 |
|---|---|---|
| observation_time | 数据观测时点（as-of），记录"我在什么时候看到这个值" | 必填 |
| release_date | 数据发布日期（官方公布日） | 必填 |
| data_period | 数据所属期（如 2026-10） | 事实与比价必填；事件日历仅数据发布类必填 |
| update_frequency | 日/周/月/季/年/不定期 | 必填 |
| window | 对比或统计所用观察窗口（如 2024-01..2026-10） | 比价与派生统计量必填 |
| source_tier | A/B/C/D（定义见第十节 1） | 必填 |
| fallback_flag | 是否使用替代指标；为真时须写 fallback_path | 必填 |
| missing_type | 缺失类型枚举（第十节 2）；数据可用时填 none | 必填 |
| value_type | 初值/修正值/估算值 | 事实必填 |
| value_kind | price/return/level/ratio/count/qualitative（第七节判据依赖此字段） | 事实与比价必填 |
| subject | 资金主体：政策/公共池/外部/机构/散户/产业资本（ADR-023）。决定这条证据"是谁的钱" | 事实必填 |
| channel | 六环通道：C1–C6（ADR-019）。决定这条证据在证据链上的位置 | 事实必填 |

| source_timestamp | 源数据自身的时间戳（原始接口或文件给出的时间，可为空） | 选填 |
| comparable_from | 可比期起点：该记录自何时起与其他记录同口径可比（用于阻断跨口径自比，见第十节 3） | 口径有断点时必填 |
| series_frequency | 派生统计量（如相关系数）所用序列的频率（日/周/月） | 派生统计量必填 |
| rule_status | ratified/draft（draft 条款不得作阶段完成判据，见附录 E） | 必填 |

事件日历与事件分支使用各自 schema（见第八节），同样须携带上表字段中适用的项。

## 五、基本面：事实与路径

资金不单独成面。本平台不设"资金维度"这一层抽象（ADR-014），两条理由：① 平台禁止任何资金方向结论，而"维度"一旦存在，读者就会沿维度推出方向；② 组织功能已由第六节的**六环（通道顺序）**承担，"维度"是重复的第三套分类。指标分组以六环为唯一来源（指标归属唯一性，第三节）。

每个事实仍需回答"它为什么出现在这里"，这是 capital_path 的用途：记录该指标与资金的关系路径（路径描述、目标观测、中间代理），供用户阅读；平台不据此推出任何方向。

> 政策设定的利率与参数（LPR、政策利率、存款准备金率）归政策状态（见第六节），不作为市场交易类指标的代理项。边界是"谁设定的"，不是"是不是利率"。

> **删除项的处置（ADR-014）：** 原"资金五维表"（存量资金/增量资金/资金成本/资金收益/资金意愿）整表删除，其分类功能由第六节的六环承担。"风险溢价"此前已按价差规则归比价层（ADR-005）。"成交额、换手率是期间流量与比率、不属于时点存量"这条结论保留，体现为第三节判别表的 value_kind 与第六节清单的实际归类。

> **V2.4 修订说明（保留）：** 2024 年 8 月 19 日沪深港通信披机制调整后，北向实时买卖额与日度个股持股数据已停止官方披露，个股持股数量仅按季度公布。故"北向净流入"不作为代理指标，"北向持股"降为季度口径。

> **北向口径细则（V2.5 补充）：** 现行官方披露为——每交易日盘后公布当日成交总额及总笔数、ETF 成交总额、前十大成交活跃证券名单及其成交总额（按月度、年度汇总）；每季度第五个交易日公布**上季度末**单只证券合计持有数量。要点三条：① 只有成交总额与名单，**没有买卖拆分、没有净额**；② 季度持股的 data_period 天然滞后一个季度，做时间自比时必须按 data_period 对齐并标注滞后；③ 任何"日度北向净流入/日度个股持股"均为第三方估算（F09）。

**呈现措辞边界：** 带正负号的资金类指标（融资净买入、基金发行份额等）本身有方向，呈现其数值与同比/环比变化属于事实呈现与比价呈现，不违反禁令；被禁止的是附加判断性语句，如"资金正在进场""增量资金充裕""聪明钱在撤离"（F18）。规则一句话：**数值可以呈现，方向性结论句不可出现。**

```json
  "comparable_from": "可比期起点（口径有断点或修正时必填）",
  "value_kind": "price/return/level/ratio/count/qualitative",
  "...": "第四节统一字段（observation_time、release_date、data_period、update_frequency、window、source_tier、fallback_flag、missing_type、value_type、source_timestamp、rule_status、subject、channel、proves、does_not_prove、series_frequency）"
}
```

政策状态的 schema：现行政策状态使用独立 schema（见第六节），不走上述通用事实 schema，也不占 derived_type；其事实类别归属仍为政策状态。derived_type 只描述普通事实的产生方式（观测/聚合/派生/序列）。**caliber_version 不在事实记录中存储**，只经 indicator_id 关联指标注册表（单一来源）；口径断点用 `comparable_from` 声明可比期起点，不复制口径版本内容。

原始序列类型事实的特别规则：仅在数据层存在，不进入呈现层（F04）；current_state 只填元数据；完整序列存 raw_series，注册时必须 `value_kind=price`；使用方式限两种——转成收益率（percent_change）后参与比价，或用于计算排名（rank）。price 类记录的任何水平值不得进入呈现层。

## 六、分层事实清单：骨架固定，条目动态

**类别骨架（市场层，ADR-019）：** 六环——C1 政策设定、C2 资金供给、C3 资金价格、C4 场内杠杆与资金池、C5 主体行为（外部/机构/散户）、C6 市场结果。六环是资金通道顺序，不是因果断言；增删环才升框架版本。板块层骨架见附录 F.2（同名同序六环 + R1–R3），**v1 不做个股层**（D10 关闭；将来要做须新开 ADR 与新骨架，不复用现有编号）。

术语消歧：本框架的"基本面"指**分析面**（一切当下的事实）；"经济基本面"这一说法自 V2.8.0 起不再作为市场层类别（ADR-019），仅在引用外部资料时出现，指 GDP/CPI/PMI 一类指标。两者同名不同义，行文与实现中不得混用。

**接入顺序不设优先级标签（ADR-024）：** 数据是否可得不由框架决定，框架因此不排先后。可得的先接、不可得的标 missing 并留空环；阶段划分只表达能力依赖（见第十七节）。

事实注册规则：任何新事实进入清单，必须通过 schema 校验，声明 layer、subtype、channel、subject、derived_type、derived_from、capital_path_id、value_kind、source_tier、update_frequency、status、supersedes、comparable_from、rule_status、proves、does_not_prove。caliber_version 在指标注册表中声明（单一来源），事实记录只存 indicator_id、通过关联查询获取口径版本，不重复存储——比价做时间自比时，先经 indicator_id 查注册表核对口径版本与 comparable_from，跨口径版本则拒绝计算。capital_path 来自独立维护的"事实→纳入路径映射表"，事实记录只存 capital_path_id。以比价结果为输入的合成指标（如拥挤度 = 换手率分位与成交额分位的合成）须在注册表声明 derived_from 指向相应 compare_id，链路可逐层追溯到原始事实。

### 市场层事实清单（六环，ADR-019）

**环的读法：** 按环自上而下排列，环内按 subject 分组；顺序表达"钱的通道"，不表达因果（"因为政策松所以钱进来"这类句子禁止出现）。

**为什么是六环：** 少一环就有断点——缺 C1 没有外生约束、缺 C4 看不到场内弹药、缺 C5 看不到谁在动、缺 C6 无法核对；多一环则重复（例如"情绪"已被 C4 的杠杆与 C6 的结果分别覆盖）。

**每条事实必填：** `subject`（政策/公共池/外部/机构/散户/产业资本）、`channel`（C1–C6）、`proves`、`does_not_prove`（ADR-023）。缺 subject 或 channel 的事实不得注册。

**空环规则：** 某环当期无任何可得证据时，呈现中必须保留环名并标 missing_type，不得静默跳过——否则读者会把"没数据"读成"没变化"。

#### C1 政策设定（subject=政策）

**逻辑理由：** 它回答“水龙头被谁拧、往哪拧”。放在链首，因为政策是**外生给定**——它改变后面五环的约束，而后面五环不能反过来改变它；所以它是起点，不是结论。它不回答传导效果与时滞（政策松了，钱未必立刻来）。

**政策状态：** 记录当前仍在生效、对资金有影响的政策状态，不记录历史发布事件。字段：policy_id、policy_domain（货币政策/财政政策/行业监管/外汇政策等）、current_status（当前政策状态描述）、status_enum（该 domain 下的可核验状态枚举，定性状态必填）、effective_since（当前状态起始时间）、supersedes（引用上一个状态记录的 policy_id）、capital_path_id、source_tier（限 A）、source_link、observation_time、rule_status。

**定性状态的可核验性（新增）：** 行业监管这类定性状态必须同时给出 status_enum 与官方依据链接（政策文本、公告、法规页）。"状态变更"的判定标准是官方文本/公告发生了变化，不是观察者的描述变化；无法给出官方依据链接的定性状态不得录入（missing_type=not_crawlable 或 pending_verification）。

supersedes 边界：supersedes 只引用上一个状态记录的 policy_id，用于追溯状态变更来源，不展开为完整历史序列。需要看历史时用时间自比（当前状态 vs 上一期数据快照），不通过 supersedes 链遍历。**状态历史快照的用途是时间自比，不是 supersedes 遍历**（第十二节存储方案按此设计）。

**口径边界（C1 vs C3）：** 政策设定的参数（LPR、存款准备金率、监管状态）归 C1；市场交易产生的价格（Shibor、DR007、国债收益率、汇率）归 C3。边界是"谁设定的"，不是"是不是利率"。同一利率若既有设定值又有成交值，按"设定归 C1、成交归 C3"分别注册，不重复。

**C1 的事实条目：** LPR、存款准备金率、政策利率、行业/外汇监管状态（定性）、降准/降息/OMO 净投放/MLF 续作（政策动作）、政府债净融资与专项债发行进度、财政存款余额（财政节奏）。

**日程指针（ADR-020）：** C1 呈现末尾固定附一行"未来 30 天政策与发布日程：N 项（详见事件情景层）"，此处不展开细节。

#### C2 资金供给（subject=公共池）

**逻辑理由：** 它回答“体系里有多少钱、结构是活是死”。排在价格之前，因为**先有量才谈价**：总量是资金价格的背景，供给决定价格的中枢。它不回答“钱会不会进股市”——钱可能停在存款或理财里。

M2 同比、M1 同比（M2-M1 剪刀差的输入）、社融存量同比及政府债分项、居民存款总额与定期化比例、财政存款余额（V2.13.6 由 C1 改归 C2）。**已删：非金融企业存款（与 M1 重叠）、外汇占款（口径争议、非主渠道）。**

**边界：** C2 是"体系里有多少钱"，不是"有多少进了股市"——M2 同比只证明货币总量扩张，不证明资金入市（须写入 proves / does_not_prove）。

> **经济基本面（GDP/CPI/PMI/社零/出口）已移出市场层（ADR-019）：** 它们不回答"资金走到哪一步"，只保留"发布日"进事件日历（由 C1 的日程指针引用）。汇率不在此处——它属市场交易价格，归 C3。

#### C3 资金价格（subject=公共池）

**逻辑理由：** 它回答“钱贵不贵”。放在供给之后、杠杆之前，因为价格是供给与需求的交点，也是**宏观的钱进入场内杠杆的桥**：借钱贵不贵，直接决定下一环敢不敢加杠杆。它不回答估值会不会重估（那需要与股息率做比价）。

DR007、Shibor（O/N、7D）、中国 10Y 国债收益率、信用利差（须声明基准）、股息率（作为资金收益率的一端）、汇率（USD/CNY 中间价、USD/CNH 即期，须注明报价口径）。

**边界：** 政策设定的利率（LPR、政策利率、存款准备金率）在 C1；C3 只放市场成交出来的价格。汇率归 C3，外部资金只引用它做 CNH-CNY 价差（比价层 spread），不重复注册为事实。

#### C4 场内杠杆与资金池

**逻辑理由：** 它回答“场内已经有多少弹药”（杠杆存量 + 自有现金）。排在价格之后，因为**杠杆是对价格的直接反应**：钱一贵，杠杆先缩；钱一便宜，杠杆先加。它不回答这些钱是谁的（主体在 C5），也不回答是不是新钱（浮盈再杠杆也会抬余额）。

两融余额、融资余额增速、融资买入额占成交额比例（以上 subject=散户：杠杆工具主要由散户与游资使用，是散户资金的代理，须标 fallback）；证券客户保证金（subject=公共池：交易结算资金池）。

#### C5 主体行为

**逻辑理由：** 它回答“分主体看，谁在增、谁在减”。放在前四环之后，因为前四环只说“总量与条件”，**只有这一环把资金落到具体的人**；没有它，只能看到水多水少，看不到水流向谁。它不回答对手方（谁卖给谁不可观测），也不回答全市场净流入（多数数据只有成交额或上榜样本）。

**外部（subject=外部）：** 北向盘后成交总额及总笔数（活跃度，**无买卖拆分、无净额**）、前十大活跃证券名单及成交额、北向季度持股数量（底仓，披露上季度末，滞后一季）、QFII/RQFII 持仓（定期报告口径）、海外中国主题 ETF 规模变动（代理，标 fallback）。

**代理观测项（需在 fallback_flag 标注）：** CNH-CNY 价差（引用 C3 汇率、按比价层 spread 输出）、H 股相对 A 股折溢价、海外中国 ETF 规模变动。

**已删除项：** 北向日度净买入、北向日度个股持股——官方已停止披露，任何此类日度数据均为第三方估算，不得进入事实层（F09）。

**机构（subject=机构）：** 龙虎榜机构专用席位净买（日）、大宗交易成交额与折溢价及买入方席位（日）、ETF 份额与净申赎（日）、公募基金新发份额（周/月）、保险/社保/公募季报持仓变动（季）。

**产业资本（subject=产业资本，V2.13.6 新增主体）：** 控股股东与董监高增减持（不定期，公告口径）。与机构并列但主体不同——它是产业资本，不是金融机构。

**散户（subject=散户）：** 新增开户数（月）、小单成交占比（日，代理：须声明单笔金额分层口径）、关注度/热搜（日，代理）。

**归属说明：** 两融在 C4 注册，C5 只引用不重算（指标归属唯一性，第三节）。北向持股按季度披露上季度末数据，时间自比须按 data_period 对齐并标注滞后。

#### C6 市场结果（subject=公共池）

**逻辑理由：** 它回答“市场怎么反应”。放在最末，因为结果是前五环共同作用后的**可观测影子**；它能让你核对“钱到底动没动市场”，但不能反推资金来源。单看 C6 只能说“结果”，不能说“资金”——这正是它排在最后、而不是排在最前的原因。

全市场成交额、涨停/跌停家数与涨跌家数分布、板块间成交额集中度、板块间涨跌幅离散度、宽基指数日线 OHLCV（仅数据层，供收益率与排名计算，不呈现）。

**边界：** C6 是"结果"，不是"资金"——单看 C6 说不出钱从哪来、进了谁的手，这正是 C1–C5 存在的理由。

**外部条件（背景，不占六环位置）：** VIX、DXY、美国 10Y 国债收益率标为"外部条件"，用于解释外部资金的意愿背景；它们不参与六环合成，呈现时单列在 C5 之后的"背景"块，并注明"不直接等于外资流入"。

**背景通道（channel=背景）放两类东西：** ① 外部条件（VIX/DXY/美国 10Y）；② 经济基本面类指标（如 CPI 同比）——它们不进六环，只作为事件分支的 `affected_indicators` 登记，避免事件面出现未注册指标。背景项不参与六环合成，也不参与 as-of 计算。

**移出市场层（ADR-019）：** 经济基本面（GDP/CPI/PMI/社零/出口）不再作为市场层指标，其"发布日"保留在事件日历；人民币国际化、大类资产框架保留但暂不实现，实现时按 subject/channel 归入相应环。

**16 项市场层资金类事实快照：** 见附录 A（原 18 项，V2.13.6 删 2 项；已按 subject/channel 重排）。

**市场层呈现顺序：** C1 → C2 → C3 → C4 → C5（外部 → 机构 → 散户）→ C6 → 背景（外部条件）。同一环内按 subject 分组。

### 板块层事实清单（优先实现）

板块资金流（净额数值）、板块内涨跌分布、板块估值绝对值、板块成交额、板块换手率、板块成交占比（占比，事实；其分位归比价层）、板块内个股相关系数（须带 window 与 frequency）、板块个股价格序列（日线，value_kind=price，不呈现）、板块现行政策状态、板块 ETF 日线 OHLCV（不呈现）。

**移出本清单的三项（V2.5）：** 板块涨幅排名、板块资金流排名、板块估值分位——排名与分位属比价层，按 result_form=rank/percentile 输出，不注册为事实（第三节规则 3）。

### 板块层六环（同名同序，内容重定义）

前提：板块层**不重复采集宏观数据**（那属于市场层）；板块层的信息增量在**结构**，不在总量。所以六环在板块层不是"市场层的缩小版"，而是"继承 + 加总 + 相对化"。L1–L6 全部适用，状态词见本节末尾。

#### C1 行业政策（subject=政策）

**逻辑理由：** 板块层唯一的**外生变量**——宏观政策已在市场层，落到板块就是行业政策。

政策载体从"货币/财政设定"换成**行业政策**：补贴、准入、监管、牌照、行业会议。多数是定性项，逐条须 status_enum + 官方链接（entry_mode=manual）。行业政策日程进**板块层事件日历**（独立维护，不与市场层合并）。

#### C2 供给份额（subject=公共池）

**逻辑理由：** 板块没有自己的货币总量，只能问“钱偏到这个板块了吗”——所以是**份额**，不是总量。

**板块层没有自己的货币总量。** C2 在此定义为"该板块在全市场中的份额"：成交额占比、市值占比、ETF 份额占比。它由 C6 的绝对量派生，**不是独立采集项**；禁止出现"板块 M2""板块社融"这类说法——那是拿一个不存在的量在编指标。

#### C3 相对贵贱（subject=公共池）

**逻辑理由：** 板块没有独立的资金价格，只有“贵不贵”——所以是**相对估值**，不是利率。

**板块层没有独立的资金价格。** C3 定义为板块估值水平（PE/PB 绝对水平）与"相对全市场的估值差"。绝对估值是事实（附录 G 的 A9 估值倍数），差值与分位属比价层（第三节规则 3、7），事实层只存绝对水平。

#### C4 场内杠杆与资金池（板块层基本为空）

**逻辑理由：** 分板块杠杆不可得，所以这一环**默认空着**；空环本身就是“这里不可知”的诚实表达，而不是拿别的数据凑。

交易所**不披露分板块两融**。只有两种做法：
1. **空环**（默认）——标 missing_type，写"不可读"；
2. **D 类派生**（可选增强）——用板块内个股两融加总，必须声明覆盖率与成分版本，并标 fallback。

默认选 1，因为它诚实；选 2 时必须能说清"覆盖了多少市值的个股"。

#### C5 主体行为（板块层最重的一环）

**逻辑理由：** 这是板块层**唯一能把“谁在动”落到板块上**的通道——靠加总（个股 → 板块），所以它最重，也最依赖 R1/R2。

- **外部**：北向持股按板块加总（季）、海外中国 ETF 中该行业基金的规模；
- **机构**：板块 ETF 净申赎、板块内个股龙虎榜机构净买加总、大宗成交加总；
- **散户**：板块 ETF 份额变化、板块内两融加总（若 C4 已做）、板块内小单占比（若可得）。

每一条加总项都必须写清：加总方法、覆盖率、成分版本（见 R2）。

#### C6 结果（板块层最强的一环）

**逻辑理由：** 板块层大多数可得数据都在这里；它最强，也说明板块层的价值在“结构”（聚散强弱），不在“总量”。

板块成交额、换手率、板块内涨跌分布、板块内个股相关系数、板块相对强弱（对全市场、对同类板块）。相对强弱的名次与分位归比价层（rank 须带 universe）。

### 三条归属规则（板块层成立的前提）

**R1 成分表版本。** 每个板块必须绑定"行业分类标准 + 版本 + 生效日"（如申万 2021 版、中证指数 2026-10 调整后）。**没有版本号时，板块层不得输出任何时间自比**——否则会静默算错，比"缺数据"危险得多。

**R2 加总口径。** 从个股加总到板块时必须声明：等权还是市值加权、是否剔除停牌/ST、覆盖率下限（如覆盖 ≥80% 市值才成立）。加总口径变更视为口径变更，须新增 caliber_version。

**R3 跨版本处理。** 成分版本变化时，**禁止把新旧版本拼成一条时间序列**；只能分段呈现，或仅做截面比较（同一时点、同一版本）。违反时按 caliber_mismatch 拒绝计算。

### 板块层的读法（L1 词表在板块层的替换）

不是"松/紧、扩/缩、贵/便宜"，而是：

| 环 | 板块层状态词 | 必须带"相对谁" |
|---|---|---|
| C1 行业政策 | 偏松 / 偏紧 / 不变 | —（行业政策本体） |
| C2 供给份额 | 份额升 / 降 / 不变 | 相对全市场 |
| C3 相对贵贱 | 偏贵 / 偏便宜 / 不变 | 相对全市场（或同类板块） |
| C4 场内杠杆与资金池 | 加杠杆 / 去杠杆 / 不可读 | —（默认不可读） |
| C5 主体 | 增 / 减 / 不变 | 分外部/机构/散户 |
| C6 结果 | 参与度升/降；广度强/弱；结构聚/散；相对强/弱 | 相对全市场、相对同类板块 |

C2、C3 的状态词**必须带"相对谁"**（对全市场 / 对同类板块），否则只是绝对量，没有板块层意义。

**板块层状态词判定表（唯一定义处）：** 与市场层同一套逻辑——只判方向、不设幅度阈值；"相对"必须写明参照对象与 universe。

| 环 | 状态词 | 判据字段 | 比较基准 | 方向映射 | 缺数据时 |
|---|---|---|---|---|---|
| C1 | 偏松 / 偏紧 / 不变 | 行业政策动作（公告/发文）与 status_enum | 上一政策状态 | 新增扶持或放宽→偏松；新增限制或收紧→偏紧；无变化→不变 | 不可读 |
| C2 | 份额升 / 降 / 不变 | 板块成交额 ÷ 全市场成交额 | 上一期同口径 | 升→份额升；降→份额降 | 不可读（分子分母都在 C6，通常可得） |
| C3 | 偏贵 / 偏便宜 / 不变 | 板块 PE（或 PB）÷ 全市场 PE（或 PB） | 上一期同口径 | 相对比值上升→偏贵；下降→偏便宜 | 不可读 |
| C4 | 加杠杆 / 去杠杆 / **不可读** | 分板块两融（D 类加总，须声明覆盖率） | 上一期 | 默认标不可读；做了加总才可判方向 | 不可读（默认） |
| C5 | 增 / 减 / 不变（分主体） | 外部：北向持股按板块加总；机构：板块 ETF 净申赎、板块内龙虎榜机构净买加总 | 上一期或可比期 | 净申赎/净买为正→增；为负→减 | 分主体写不可读 |
| C6 | 参与度 升/降；广度 强/弱；结构 聚/散；相对强 / 相对弱 | 板块成交额；板块内上涨家数占比；板块内相关系数；板块涨幅 rank（须声明 universe） | 上一期 / universe | 占比 >50% 强、<50% 弱；相关系数升→聚；rank 前 1/3 强、后 1/3 弱 | 缺哪项写其余项，不猜 |

三条附则：① **相对类状态词必须写出参照对象与 universe**（"相对全市场""申万二级 31 个板块"），否则无法复核；② C2、C3 的分子分母必须同版本成分表（R1）；③ C4 默认不可读，不得用"板块内个股两融加总"以外的数据代替。

### 有限数据下的断言（L3 在板块层的落地）

板块层空环通常比市场层多（C4 常空，C2/C3 是派生）。按 L3：

- C2/C3 是派生项 → 只能写"份额变化""相对贵贱"，**不得**写"供给扩张""资金变贵"；
- C4 空 → 该环写"不可读"，且整段**不得**出现"杠杆在加/去"；
- 六环里只剩 C5/C6 有直接证据时，板块层读数只能是**结构状态**（聚散、强弱），**不能说**"资金在流入某板块"——那需要 C5 的净额证据，而板块层多数时候只有份额与排名。

### 个股层事实清单（**v1 不做**，仅留作将来扩展参考）

个股财务、个股资金流、个股情绪、个股现行公告状态（已落地公告的当前状态，不记录历史公告流）、个股所属板块与行业分类、个股日线 OHLCV（不呈现）。

**个股层骨架（附录 F.3）：** 公司财务、公司资金、公司情绪、公司公告状态、公司分类五类——**v1 不实现**。

### 读法规则（L1–L6，跨环跨层适用）

这六条规则不定义数据，只定义"怎么读"。没有它们，六环只是一堆数字；有了它们，读法可以被复核。**逻辑链允许断**——断点必须可见（空环写"不可读"），且不得用跨环合成句掩盖断点。

**L1 状态词封闭。** 每一环的读法只能用有限状态词，其余一律写数值与口径：

| 环 | 允许的状态词 | 判据 |
|---|---|---|
| C1 政策开关 | 偏松 / 偏紧 / 不变 | 按设定值变化与政策动作方向；只描述设定，不推传导 |
| C2 总量 | 扩 / 缩 / 不变（附：结构偏活 / 偏死） | 按同比方向；结构看 M1 相对 M2 |
| C3 价格 | 变贵 / 变便宜 / 不变 | 按同期限利率方向；不同期限不可混读 |
| C4 场内杠杆与资金池 | 加杠杆 / 去杠杆 / 不变；现金池 增 / 减 / 不变 | 两融余额与客户保证金**分开读**，方向可背离 |
| C5 主体 | 增 / 减 / 不变 | 外部/机构/散户各自单独读，不合并 |
| C6 结果 | 参与度升 / 降 / 不变；广度强 / 弱 / 不变；结构聚 / 散 / 不变 | 成交额、涨跌分布、板块集中度与离散度 |

**状态词判定表（L1 的执行细则，唯一定义处）：** 状态词只能由"单个字段的方向"决定，**不设幅度阈值**（唯一例外：广度用 50%）——阈值一旦引入，就等于在替用户拍板。

| 环 | 状态词 | 判据字段 | 比较基准 | 方向映射 | 缺数据时 |
|---|---|---|---|---|---|
| C1 | 偏松 / 偏紧 / 不变 | 政策设定值（LPR/准备金率）与政策动作 | 上一期设定值 | 下调→偏松；上调→偏紧；无变化→不变 | 不可读 |
| C2 | 扩 / 缩 / 不变 | M2 同比（或 M1/社融同比替代） | 同比值的符号 | >0 扩；<0 缩；=0 不变 | 不可读 |
| C2 附注 | 结构偏活 / 偏死 | M2 同比 − M1 同比（剪刀差，比价层输出；operand_order 见 ADR-002） | 剪刀差的符号 | >0 偏死（M2 快于 M1）；<0 偏活 | 不写附注 |
| C3 | 变贵 / 变便宜 / 不变 | 同期限利率（DR007 / 中国 10Y） | 上一期同期限值 | 上升→变贵；下降→变便宜；相等→不变 | 不可读 |
| C4 | 加杠杆 / 去杠杆 / 不变；现金池 增 / 减 / 不变 | 两融余额；**货币基金规模（客户保证金停发后的代理）** | 各自上一期 | 升→加/增；降→去/减 | 两项分开写不可读 |
| C5 | 存量 增/减/不变；活跃度 升/降/不变 | 外部：季度持股（存量）、成交总额（活跃度）；机构：龙虎榜机构净买、ETF 净申赎；散户：常不可读 | 各自上一期或可比期 | 升→增/升；降→减/降；（净买为正→增、为负→减） | 分主体写不可读；散户可写"引用 C4" |
| C6 | 参与度 升/降/不变；广度 强/弱/不变；结构 聚/散/不变 | 成交额；上涨家数占比；板块成交集中度 | 各自上一期 | 占比 >50% 强、<50% 弱；集中度升→聚、降→散 | 缺哪项就只写其余项，不猜 |

三条附则：① 同一环内多个字段**分别写、不合并**（如"短端变贵、长端变便宜"）；② "强/弱"只指相对排名位置或 50% 阈值两侧，不含预期；③ **任何状态词都必须能指回一个具体字段与比较基准**——指不回去的就不是状态词，而是判断。

禁止使用"资金活跃""情绪偏弱""资金面宽松""增量资金充裕"这类无边界形容——它们无法被数据复核，也无法被推翻。

**L2 替代合法性与强度三档。** 换证据，不换问题：

1. **直接**（同口径、同 attribute + transform）：结论可用原措辞。
2. **同属性替代**（属性相同、口径不同，如 DR007 → GC007）：结论须带口径说明，写"（替代：GC007，场内口径）"。
3. **跨属性近似**（如拿成交额增速替货币总量增速）：**只能写"方向参考"**，不得进入状态词，且必须标 fallback_flag 与 fallback_path。

替代不得改变 attribute 与 transform；改变了就不是替代，而是换问题。跨属性近似永远不能被写成"直接"。

**L3 断言强度 = 链上最弱一环。** 整页能说到哪一句，由最弱那一环决定：

- 六环都是"直接"证据 → 可输出六环状态并列的完整读数；
- 某环为"同属性替代" → 该环状态词后必须带替代说明；
- 某环为空或无源 → 该环写**不可读**，并且**整页不得出现跨环合成句**（如"资金整体在收缩""增量资金在撤退"）；
- 平台产出物 = 在现有证据下最多能说到的那一句，不是结论。

**L4 读法句之间禁止因果连词。** 只能并列（"C1 偏松；C3 变贵"），不得写"因此 / 所以 / 导致 / 意味着"。环的顺序是读的顺序，不是因果链——连线由用户自己做。

**L5 时间基准与时效。** 六环频率差很大（不定期/月/日），"现在"必须被定义，否则同一页里月度和日度混读会误导。

1. **页面 as-of = 最慢一环的 data_period。** 六环中 update_frequency 最慢的那一环决定整页"截至何时"；页首必须写 `as-of`（如 `as-of 2026-10`）。
2. **快频环只作"区间内最新读数"。** 日频环（C3/C4/C6）在月频 as-of 下，状态词后必须括注自身数据期：`C6 参与度升（2026-11-20）`。
3. **每个状态词都要带数据期与发布日**，不得只写"目前""最近""近期"。
4. **方向必须有前值。** 没有前值（首次发布、口径断点、新接入）时，该环只能写"水平值 + 方向待补"，不得猜方向。
5. **过期判定见第十节 2**：`as-of − data_period > 2 × update_frequency` 标 stale、> 3 倍视为不可读；stale 项在元信息段逐条列出。
6. **不得跨频对齐**：月频的变化与日频的方向不能放进同一句里比较；不同频率只并列、不合成（L3、L4 已覆盖）。

**L6 主体间不得编造对手方。** C5 的三个主体各自读"自身在增/在减"，到此为止。禁止写"机构接盘、散户出货""资金从散户流向机构""外资在撤离 A 股"这类叙事——成交是双向聚合的，平台没有对手方数据：龙虎榜给的是**上榜个股的买卖席位**（不是全市场对手方），北向只有成交总额（无买卖拆分）。唯一例外是**标的级**的席位买卖明细，可写"该股当日买方席位为…"，但不得外推为"某类资金整体在出货"。

**三个读例（用来校准措辞；注意 as-of 与数据期）：**

- 六环齐全：`as-of 2026-10（由 C2 决定）；C1 偏松（2026-10-20）；C2 扩、结构偏活（2026-10）；C3 变便宜（2026-11-20）；C4 加杠杆、现金池增（2026-11-20）；C5 机构增（2026-11-20）、散户减（2026-09）、外部不可读；C6 参与度升（2026-11-20）、广度弱、结构聚。`
- 只有结果环：`as-of 2026-11-20；C2/C3/C4/C5 不可读；C6 参与度升、广度弱。` —— 到此为止，不得补"说明资金在撤离"这类合成句。
- 有替代时：`C3 变贵（替代：GC007，场内口径，2026-11-20）；C2 扩（直接）` —— 替代项必须带口径，跨属性近似只能写"方向参考"，不得进状态词。

## 七、比价：同质前提下的时间自比与空间互比

比价 = 同一数据不同时间的对比，或同性质数据同一时间的对比。

时间自比：同一数据、同一口径、不同时间点。

空间互比：度量同一属性的两个实例、同一时间点。

叠加：内层空间互比，外层时间自比。schema 实现方式：内层比价记录有 compare_id，外层比价的 inputs 以 compare_id 引用内层结果（附录 B）。

同性质 = 度量同一个属性，不要求指标名称相同。占比不满足，相关系数不满足。

锚点：同质锚、属性锚、口径锚、窗口锚、层级锚、归属锚、量纲锚。

**锚的可判定性（ADR-013 / ADR-017）：** 七锚中五个可机械判定——**层级锚**（同层，或"细层 ↔ 其所属粗层"且归属声明有效）、**归属锚**（跨层时必须给出归属来源与版本：板块成分表、行业分类标准）、**口径锚**（caliber_version 与 comparable_from）、**窗口锚**（window 相容且起点不早于 comparable_from）、**量纲锚**（单位/币种/频率可比）。同质锚与属性锚依赖指标注册表：每个指标声明 `attribute`（被度量的基变量属性，如价格水平/收益率/时点存量/汇率）与 `transform`（level 原值 / yoy 同比 / mom 环比 / cum 累计）；**同质锚判据 = 两者 attribute 相同且 transform 相同**，否则一律拒绝（F06）。**未声明 attribute 或 transform 的指标不得参与比价**，不允许由模型凭语义裁量放行。属性本体、变换、量纲组与算子白名单见附录 G。

比价输出 schema：见附录 B（含 compare_type、compare_operation、result_form、operand_order、universe、reference、anchor、inputs、current_state、series 与第四节统一字段）。

**默认窗口（ADR-027）：** 请求未指定窗口时按下列默认值执行，不得临场决定——① 时间自比：最近 20 个可比期（按该指标 update_frequency 计，日频=20 个交易日、月频=20 个月）；② 分位：近 3 年，且窗口起点不早于 `comparable_from`（不足 3 年时按可比期计算并在元信息段标注）；③ 相关系数：60 个可比期，`series_frequency` 与数据频率一致；④ 任何默认值都可被请求参数覆盖，覆盖后须在元信息段写明 window 与来源（默认 / 用户指定）。

**操作数顺序（新增）：** difference/spread/ratio/percent_change 必须声明 operand_order（A−B 或 A/B，谁是被减数/分子）。未声明不得输出，符号方向不得靠"惯例"推断。本文"剪刀差"一律定义为 **M2 同比 − M1 同比**；引用外部资料若按 M1−M2 口径，须换算并注明。

**rank 的对照全集（新增）：** result_form=rank 必须声明 universe（全市场/指定板块集合/指数成分）与排序方向；universe 变化视为口径变更，前后两名次不可直接比较。

**偏离度定义（新增）：** 偏离度不是第六种 result_form，而是 difference/spread + result_form=point_value 时的一种呈现，必须声明 reference（对比基准：窗口均值/中位数/上期值/参考线）。未声明 reference 不得称为偏离度。

**比价序列折线呈现规则（V1/V2 机械判据，替代原"正反例"清单）：**

- **判据 V1（可渲染）**：series 的 value_kind 为 return/level/ratio/count，且不满足 V2 任一条件 → 可渲染折线。
- **判据 V2（禁渲染）**，满足任一条即禁止：
  - V2-a 输入中存在 value_kind=price 且操作未先转为 return（如两个收盘价直接相除、相减）；
  - V2-b series 的 value_kind 为 price，含 base100 归一化后的价格曲线与"指数 A/指数 B"比值曲线（形态与相对价格走势同构，属价格结构判断的输入）；
  - V2-c 序列为单一标的的 OHLCV 任一分量。
- **可渲染示例**：M2-M1 剪刀差序列（各自 percent_change 后相减）、PE 历史分位序列、股息率−国债收益率利差序列、板块成交占比序列、板块涨幅排名序列。
- **禁渲染示例**：任何单边价格序列；OHLCV 任一分量；两个价格水平的比值或 base100 曲线。
- **主用例裁决（ADR-001）**："板块 ETF 对宽基指数"这类比价允许，且仅允许两种输出形式：① 两边各自 percent_change 后 difference（超额收益率序列，value_kind=return）；② 按收益率做 rank 对比。禁止输出两者价格水平的比值或 base100 曲线。实现判据：注册表把 ETF 与指数标为 value_kind=price 后，算子白名单（附录 G）自动只放行 percent_change→difference 与 rank 两条路。

比价的禁止输出见 F05、F06。

**背离标注规则（ADR-015，按分组多数判定）：** 方向 = 数值变化方向（上升/下降/不变），与利好利空无关。判定单位是**呈现分组**（六环的环，如"C2 资金供给""C6 市场结果"），不是指标两两配对：

1. 组内每个指标先各自定方向（本期 vs 最近可比期，按各自 update_frequency 取）；
2. 组内方向全部一致 → 记"同向"；
3. 组内出现方向相反 → 记"存在背离"，并列出与多数方向相反的指标名（多数 = 组内计数最多的方向；上升与下降数量相等时记"方向分歧（无多数）"）；
4. 不变（持平）的指标不参与多数计数，但在元信息段列出；
5. 不计算强度、不判定谁对、不排序、不合成单一信号；
6. **环内只有 1 条证据时不判背离**，写“单指标，不适用”——否则“方向全部一致”必然成立，等于用无信息的标注冒充结论。

这样"大部分指标显示扩张、个别显示收缩"就是一次背离标注，不需要参照系，也不产生 N×N 组合。**不标注"背离强度"**（ADR-004）：强度需要对幅度加权，与本框架定位冲突且无客观口径。

比价输入方原始数值的核对规则：比价记录内部不携带输入方原始数值（附录 B 的 inputs 只存 ID 与元数据）；事实层的同一指标照常按事实层规则呈现，两处通过 indicator_id 关联、不重复呈现同一数值。如需核对原始值，请至行情软件。

## 八、事件面（事件驱动）

事件面 = 事件日历（输入）+ 事件分支枚举（输出），两者一体。事件面的禁止项见 F08，本节只定义结构与判定规则。**呈现位置：** 事件情景层排在事实层与对比层之后（第三块）；C1 末尾的日程指针指向本节（ADR-020）。

事件窗口：未来 30 天。可配置，默认 30 天。

事件日历更新规则：事件日历每日检查一次更新；有新公告时事件驱动更新。无新公告且无事件状态流转时，保留现有日历与分支，不重新生成，observation_time 不变；有新公告或事件状态流转时，整个日历与基于它的全部可能结果分支一起重新生成，并生成新的 calendar_version（快照规则见 8.3）。重新生成不销毁历史——已发生、已取消的事件以状态字段保留（软删除），每次整历重生成时保留上一版日历快照（含 observation_time 与 calendar_version），供追溯"某事件何时进入/退出日历、状态何时流转"。

### 8.1 事件日历（事件面输入）

事件日历只维护"未来预定"事件的活动视图。事件一旦发生（结果公布），状态由"未来预定"流转为"已发生"；事件取消，状态流转为"已取消"。状态非"未来预定"的事件不再出现于默认呈现，但记录保留，可通过快照追溯。事件日历不是历史事件库。

确定性标准："已确定日期"指发布日期已由官方公告或官方日历明确列出的。媒体推测、惯例推断、通常日期一律不算。官方源优先；媒体推测不算已确定事件。

**录入方式与来源要求（新增）：** 日历条目必须有 `entry_mode`（auto/manual）。manual 条目必须给出 `source_link`（官方页面 URL）且 source_tier=A，observation_time 为录入时间；给不出官方 URL 的，不得录入为"未来预定"（只能作为线索不计入日历），与第十节"传闻不进入任何 source_tier"一致。

事件日历不标受影响指标。事件本身只说明"会发生什么"，不知道结果就不知道影响哪些指标。指标标注放在事件分支里，因为不同结果影响不同指标。

事件日历数据源范围：国家统计局发布日历、央行公告日历、交易所公告、证监会/发改委会议公告、上市公司公告（财报披露日、解禁日）、行业会议公告。具体源在实施时确定，官方源优先。官方日历的可抓取性（页面结构稳定性、有无反爬、更新及时性）是第零阶段验证项，见第十七节与附录 C。

事件日历 schema（特有字段；通用字段见第四节）：

```json
{
  "event_id": "唯一标识",
  "event_type": "数据发布/政策会议/财报披露/解禁/指数调整/其他",
  "layer": "市场/板块/个股",
  "event_date": "事件日期",
  "event_time": "具体时间（如 09:30，可空）",
  "scope": "涉及的市场/板块/标的范围",
  "data_period": "数据所属期（数据发布类必填）",
  "event_status": "未来预定/已发生/已取消",
  "status_changed_at": "状态流转时点",
  "issuer": "发布机构",
  "entry_mode": "auto/manual",
  "source_tier": "A/B/C/D",
  "source_link": "官方页面 URL（manual 必填）",
  "calendar_version": "所属日历版本号",
  "observation_time": "该日历条目的记录时点",
  "missing_type": "缺失类型枚举"
}
```

### 8.2 事件分支枚举（事件面输出）

事件分支 schema：

```json
{
  "event_id": "关联的事件",
  "event_summary": "事件简述（日期、类型、对象）",
  "observation_time": "分支枚举的生成时点",
  "calendar_version": "基于哪一版日历生成",
  "prev_value": {
    "indicator_id": "该事件发布/改变的指标（来自注册表）",
    "value": "前值",
    "data_period": "前值所属期",
    "source_link": "前值出处（官方发布页）",
    "observation_time": "取到前值的时点"
  },
  "possible_outcomes": [
    {
      "outcome_label": "分支名称",
      "observable_flag": "该分支生效的事件层面可观测标志（必须是可机械比对形式，如 公布值 > 前值）",
      "observable_flag_source": "该标志的验证来源（如 国家统计局 CPI 发布页、交易所公告）",
      "affected_indicators": ["MKT_CPI_YOY"]
    }
  ],
  "branch_ordering": "排序规则文本（见下）",
  "branch_ordering_applicable": "true/false（前值不可得时为 false）",
  "no_prediction_statement": "以上为可能结果分支的枚举与事件层面可观测标志，不预测哪个分支会发生；受影响指标为客观标注，不含方向判断；价格层面的印证由用户在外部 K 线平台完成"
}
```

affected_indicators 取值约束：必须是指标注册表中的 indicator_id（该事件发布或改变的指标），不得自造名称；只标"受影响"，不写影响方向（F08）。

**分支条件不生成比价（ADR-022）：** `observable_flag` 里的"公布值 > 前值"等比较是**分支定义条件**，属可能域，不是一次事实对比——它不生成 compare 记录、不进入比价层、不参与背离计数。`prev_value` 只作定义分支的参照点。

**前值来源（ADR-018）：** 前值优先**随发布同源获取**——官方发布页通常同时给出公布值与上期值，这是最省事的路径，也不需要平台先有历史库。取到后写入分支记录的 `prev_value`，并核对三件事：① 前值是否为同一 caliber_version（口径改了就不是同一前值）；② 是否为修正后的值（修正会改动前值，须保留初值并标 value_type）；③ 官方给的是"上期值"还是"上年同期值"，两者不可混用。官方不给前值时，才回退到平台事实记录（只读取值，不写入）；两条都不可得 → `branch_ordering_applicable=false`。事件面对事实层是"只读引用"，这与"三层各自独立"不冲突——独立指的是日历条目跨层不合并，不是数值不能引用。

分支定义规则：

- 数据发布类：按"高于前值 / 低于前值 / 持平"或"高于某客观参考值 / 低于某客观参考值"定义。不使用一致预期。
- 会议类：按"有实质性决议 / 无实质性决议 / 延期"或事件本身的客观进程定义。
- 解禁/指数调整类：按"按公告执行 / 变更 / 取消"定义。

**持平判定（新增）：** 以官方公布精度为准——公布值与前值按官方公布位数四舍五入后相等即记"持平"。不得自行设定容差，不得用"基本持平"等模糊表述。

每个分支必须有事件层面的可观测标志，且标志必须是可机械比对的形式（如"公布值 > 前值"），不能含"好于/差于/积极/消极"等方向词。标志必须标明验证来源（observable_flag_source）。

分支默认排序规则：数据发布类按公布值相对前值的大小从高到低（高于前值 → 持平 → 低于前值）；会议类按事件进程先后；解禁/指数调整类按公告执行状态。排序是中性的（按数值或事件进程），不按可能性。

**排序不适用规则（新增）：** 前值不可得（首次发布、口径变更、上游未披露）时，`branch_ordering_applicable=false`，显式标注"排序不适用：前值不可得"，分支按 outcome_label 字典序排列（机械、中性），不得改用推测的前值。

事件面的禁止输出见 F08。其中两项的理由在此说明：不做历史同类事件统计拟合——历史重复的是规律，不是具体事件；统计拟合的样本少、口径杂、不可复核，会让平台暗示"这次可能重复上次"，承担了判断功能。不使用一致预期数据——一致预期是把别人的判断引入平台，让平台承担了判断功能，违反"平台只枚举可能、判断归用户"的定位。两项都"不是因为数据不可得"。

事件面（事件驱动）与价格结构推断的边界：平台做前者，不做后者。事件分支用途是：用户带到 K 线平台印证，平台不留痕。

### 8.3 日历快照与保留期（新增）

- 每次整历重生成递增 `calendar_version`（整数），整历条目的 observation_time 同步更新为该版本生成时点。
- 保留策略：保留全部历史版本至少 90 个交易日；另按每月 1 日所在版本长期保留 24 个月。存储实现见第十二节 12.3。
- 查询接口：`get_calendar(as_of=日期)` 返回该时点生效的版本；`diff_calendar(v1, v2)` 返回条目进入/退出/状态流转/字段变更三类差异。
- 事件分支归档：每次重生成后，被替代的旧分支整批归档，键为（event_id, calendar_version），不覆盖、不删除。

事件面 Skill：event-calendar（输出事件日历，事件面输入层）、event-scenario（输出事件分支枚举，事件面输出层）。

## 九、呈现形态：事实—对比—事件情景三层并列展开

输出结构固定为下述六段，字段与顺序不得变更（模板与渲染前校验见附录 D）；禁止项见 F01、F03。

**① 事实层：** 各子类事实的原始数值、聚合值、派生指标、派生统计量、时间戳、时间轴与来源字段、纳入路径（capital_path）、主体与通道（subject / channel）。**按六环顺序排列：** C1 政策设定 → C2 资金供给 → C3 资金价格 → C4 场内杠杆与资金池 → C5 主体行为（外部→机构→散户）→ C6 市场结果 → 背景（外部条件）；同一环内按 subject 分组，空环保留环名并标 missing_type。每行必须带 `proves` / `does_not_prove` 两句话。原始序列类型事实（OHLCV）不进入本节（F04）。默认输出格式为**证据行**（附录 D.1.1）：`状态词（数据期）｜依据：字段=数值+比较｜边界：不说明…`；仪表盘可用紧凑版（只留状态词）。

**事实层列白名单（ADR-016）：** 指标名、数值、单位、data_period、release_date、source_tier、missing_type、observation_time；派生统计量可加 window 与 series_frequency。**黑名单：** 同比、环比、分位、排名、偏离度、背离——这些一律只在对比层出现，不得以"列"的形式混进事实表。

**② 对比层：** 比价对比结果、compare_operation + operand_order + result_form、分位、偏离度（须带 reference）、锚点声明、时间轴字段、背离标注（按第七节分组多数规则：同向 / 存在背离 + 反向指标名）；比价 series 按第七节 V1/V2 判据渲染折线。非同质跨资产对比单独置于"跨资产并列（非同质，仅参考）"区块。

**③ 事件情景层：** **首条固定为日程指针回执**（"与 C1 指针一致：未来 30 天政策与发布日程 N 项"），随后呈现"未来 30 天事件日历"（时间表：日期、类型、对象；仅含 event_status = 未来预定 的条目）。事件分支为可选附加层，按需展开——展开时对每个事件呈现分支列表（可能结果分支、事件层面可观测标志、标志验证来源、受影响指标）。明确标注"不预测哪个分支会发生；到 K 线平台印证"。

事件日历与事件分支的关系：同一事件在两处出现是设计如此——日历回答"什么时候会发生什么"，分支列表回答"这个事件可能有哪些结果"。两者通过 event_id 关联。

**④ 跨资产并列（非同质，仅参考）。**

**⑤ 元信息：** 本批数据的 observation_time、calendar_version、缺失清单（missing_type 汇总）、口径提示（含口径断点与可比期起点）、rule_status 汇总（哪些输出基于 draft 条款）。

**⑥ 固定尾句：** "以上为客观事实、对比数据与事件分支枚举；价格结构判断与决策请自行完成，事件分支请到 K 线平台印证。"

呈现规则：层与层、面与面之间并列陈列，标注同向/存在背离，不做综合，不替用户连线；锚点不一致时不做数值比较（该比价不输出，F06）；事实缺失、数据过期时显式标注；默认展开比价层，事实层可折叠或按需展开；事件情景层整体默认展开（层内事件日历可见、仅含"未来预定"条目，事件分支按需展开）。

**数据过期（stale）：** 判定规则统一在第十节 2（阈值见 data/thresholds.json（默认 2 倍标 stale、3 倍阈值视为不可读）。呈现时标"旧值（所属期）"；stale 不改变数值，只标注时效，不得用它支撑状态词（L3）。

## 十、事实口径规范

> 标 **draft** 的条款为待核对口径（见附录 E）：生效但不得作为阶段完成判据。第 6、7 条为 V2.3 原文照录。

### 1. 数据来源 A/B/C/D 四层分级（D03，V2.128.0 定稿）

| 层级 | 定义 | 示例 |
|---|---|---|
| A | 官方一手源：发布机构官网、官方日历、法定披露平台 | 国家统计局、央行官网、交易所公告、巨潮资讯网 |
| B | 官方数据的结构化转售/授权分发，口径可溯源至 A | 持牌数据商转发的官方统计数据、交易所授权行情 |
| C | 商业终端/资讯平台的二次加工数据，口径不可完全溯源 | 行情终端加工指标、资讯平台整理数据 |
| D | 平台基于 A/B/C 数据自行计算出的派生结果（可复算、可追溯输入） | 板块成交占比、板块内个股相关系数、拥挤度（合成指标） |

规则：事实层数据原则上只用 A/B 类源；C 类源数据必须标注 source_tier=C 且不得伪装为 A/B；D 类派生结果必须可追溯计算过程与输入数据（derived_from 必填，输入数据本身须为 A/B/C 类并如实标注）；媒体、自媒体、市场传闻、日期推测不进入任何 source_tier——它们不是数据，仅可作为事件日历的线索，且须待官方确认后事件才能转为"未来预定"（F10）。

**四条边界（V2.128.0）：** ① **开源库（akshare 等）记 C**，除非**直连官方域名**且**已抽样核对**（两条都满足才可升 B）；② **媒体与传闻不入任何层级**（F10）；③ **C 类只在"该指标/口径没有 A/B 证据"时使用**——此时它是唯一可得数据，用它并标注；若同一指标已有 A/B，则不用 C；④ **升 B 的两道门槛**：(a) 取数代码直连官方域名（可自动核查，记于 `data/provenance.json` 的 `hosts`）；(b) 抽样把页面值与取数值比对并写入 `data/official/<id>.json`。



**两条易混关系（V2.5 澄清）：** ① D 类是"结果由平台算出"，**不是**"平台算不出"——平台算不出的量不产生记录；② `requires_manual_computation` 描述的是"输入存在但需人工介入才能得到"的另一种情形，与 D 类不互指（见下节），原文"对应 source_tier=D"的表述已删除；③ D 类示例不含"分位"：分位与排名归比价层（第三节规则 3），不作为 D 类事实。

### 2. 数据缺失标准化字段（missing_type 枚举，D04，V2.128.0 定稿）

> missing_type 的语义为"该数据为何未呈现/不可直接用"，不限于字面缺失。数据可用时填 none。

| 枚举值 | 含义 |
|---|---|
| none | 数据可用，无缺失 |
| not_yet_released | 未到发布时间 |
| stale | 已发布但超过更新节奏仍未更新：`as-of − data_period > 2 × update_frequency`（时效标注，判定规则见本节末尾） |
| source_unavailable | 数据源不可达/接口失败 |
| discontinued | 官方已停止披露（如北向日度持股） |
| paywalled | 数据存在但当前权限不可得 |
| not_crawlable | 官网有数据但无法结构化抓取（如图片日历、扫描件 PDF） |
| out_of_scope | 超出平台精度边界（如分钟级数据） |
| pending_verification | 已获取但尚未与官方源核对 |
| not_applicable | 该标的/层级不适用此指标 |
| caliber_mismatch | 口径不一致：数据存在但口径不同，不能直接比较（如 CPI 口径调整前后的序列、M1 新旧口径） |
| frequency_mismatch | 频率不匹配：数据存在但频率不同，不能强行同步（如日度指标与月度指标并排） |
| requires_manual_computation | 数据存在但需人工介入（如仅以图片/扫描件发布、需手工抄录）才能得到，且平台当前不具备自动处理条件。**平台可自动计算的派生量（占比、相关系数）算完即记正常事实，不标此项**；分位与排名归比价层，同样不标此项 |

**stale 判定规则（唯一定义处）：** 以 `as-of`（见 L5）减去 `data_period`，与 `update_frequency` 比较：

| 距上次更新 | 判定 | 呈现要求 |
|---|---|---|
| ≤ 2 倍 | 正常 | 不标 |
| > 2 倍 | `missing_type=stale` | 标"旧值（所属期）"；该环状态词后必须带数据期 |
| > 3 倍 | **不可读** | 该环写"不可读"，不得用于支撑状态词（L3），也不得参与背离计数 |

三条边界：① 周期换算——日频按交易日、周频按自然周、月频按自然月、季频按自然季；② `not_yet_released` 是"这一期还没到发布日"，`stale` 是"早该有却没更新"，两者不混用；③ `discontinued` 是官方停更（如北向日度持股），不占用 stale。

### 3. 数据发布日期 vs 数据所属期（D05，V2.128.0 定稿）

- data_period 指数据描述的经济区间（如"2026 年 10 月 CPI"的所属期是 2026-10）；release_date 指官方公布的日期（如 2026-11-10）。两者必须分别记录，不得混用。
- 比价的时间自比一律按 data_period 对齐，不按 release_date 对齐。
- 呈现时同一面板内的多个指标若 data_period 不一致（如月度 CPI 与日度两融余额并排），必须各自标注所属期，不做隐式对齐。
- 披露滞后的指标须显式标注滞后（如北向季度持股披露的是上季度末数据），时间自比时按 data_period 对齐并说明滞后。

**口径断点规则（新增）：** 官方口径发生变更时（如 M1 自 2025-01 起纳入个人活期存款与非银支付机构客户备付金，央行按可比口径回溯至 2024-01），新口径记录的 `comparable_from` = 口径生效期或官方回溯起点，取较晚者；旧口径记录的 comparable_from 保持原值。**跨断点不得做时间自比**（F11）：比价工具先比较双方 comparable_from 是否都覆盖 window 起点，不覆盖则拒绝计算并填 caliber_mismatch。

**comparable_from 的认定（V2.128.0 定稿，四条）：** ① 以**官方口径变更文件**的回溯起点为准（如 M1 回溯至 2024-01 → 2024-01-01）；② 官方未给回溯期时，取**断点后第一期**，并在元信息注明"官方未回溯"；③ **平台不得自行估算可比期**；无官方声明的断点一律只做截面、不做时间自比；④ **认定人是人工**——在指标注册表登记 `comparable_from` 与官方链接（`entry_mode=manual`），模型不得临场判断。

### 4. 数据替代规则 Fallback Logic（D06，V2.128.0 定稿）

总原则：优先降级到同属性的替代指标并显式标注 fallback_flag=true 与 fallback_path，绝不编造数值、绝不静默换口径。替代示例（非穷举，新增替代须走事实注册规则）：

1. 官方指标停发 → 使用同属性商业源指标，source_tier 相应降级并标注。
2. 日度数据不可得 → 降级到周度/月度同属性指标，update_frequency 如实标注，不得把低频数据伪装成日度。
3. 指标口径变更 → 新旧口径并行展示一个过渡期，caliber_version 区分，不做拼接。
4. 单一标的序列缺失 → 用同板块 ETF 序列替代，并标注替代关系。
5. 替代后仍不可得 → 如实填 missing_type，宁缺毋假。

**替代的批准与留痕（V2.128.0 定稿）：** ① **留痕三件套**——`fallback_flag=true`、`fallback_path`、降级后的 `source_tier`，缺一不可；② **分档使用**——同属性替代（attribute 与 transform 相同）可进状态词，跨属性近似只能写"方向参考"、不进状态词；③ **审批阈值**——只有跨属性近似或档位跌两级以上（如 A→C）才需人工确认一次，同属性降一级（A→B、B→C）自动放行。

**铁律：替代换的是证据，不换问题。** 拿不到"机构净买"，不能用"成交额"去回答"谁在买"——那已经不是替代，是改题；此时只能写"不可读"。替代项的数据期与主口径不一致时必须标注（如月度替代日度，状态词须带所属期，不得说"今天"）。

### 5. 关键口径约束（D07，V2.128.0 定稿）

> **V2.128.0 定稿说明：** 第 4 条坚持不变（政策状态只认 A 类源）；#17–#19 正式纳入。执行细则："剪刀差"固定为 **M2 同比 − M1 同比**，不得反用；排名全集变更按口径变更处理。

抽象原则（1–8）：

1. 不同频率数据不强行同步到同一时间轴。
2. 不同口径数据不直接相除/相减，除非口径锚声明一致。
3. 初值与修正值区分记录（value_type + revision_seq），修正后新增记录但保留初值记录（revision_seq=0 永不覆盖）。
4. 估算值必须标注 value_type=估算值，且不得进入事实层"现行政策状态"子类——政策状态只接受官方口径的 A 类源（政策参数由政策制定方公布，本身必有官方一手值），不接受估算值或第三方转售值。
5. 汇率类对比必须注明报价口径（中间价/即期、CNH/CNY）。
6. 金额类指标标注币种；收益率类指标标注发行体与市场（如"中国 10Y""美国 10Y"），不得简写为同名"国债 10Y"。
7. 分位数必须标注 window，窗口变更视为口径变更；**窗口起点不得早于 comparable_from**。
8. 相关系数必须标注 window 与 series_frequency，日频与周频结果不可混比（对应字段为 window 与 series_frequency）。

具体口径约束（9–16，与上条连续编号）：

9. **北向资金口径：** 以 2024-08 信披新规后的官方披露为准（盘后成交总额、前十大活跃证券名单及成交额、季度持股），详见第五节与第六节；任何日度北向净流入/日度个股持股均为第三方估算，不进事实层（F09）。
10. **CIPS 口径：** CIPS 处理全部人民币跨境支付（贸易、FDI、证券投资等），不能用其交易量单独推导外资流入 A 股。
11. **证券投资项结售汇口径：** 银行结售汇的证券投资项同时含股票、债券等多类资产且含存量调整，不能直接等同于外资 A 股净买入。
12. **外汇占款口径（条目已于 V2.13.6 删除，仅留警示）：** 若将来重新接入，央行外汇占款仅反映央行购汇行为，不能单独称为外部资金总源头。
13. **CNH-CNY 价差口径（对应原则 5）：** 必须注明报价方式（USD/CNH − USD/CNY），正值表示离岸人民币相对在岸更弱；未注明报价口径时不解释价差。
14. **SWIFT 口径：** SWIFT 人民币支付份额基于报文流量且含金融交易，不等于贸易结算份额；经 CIPS 清算的人民币支付不反映在 SWIFT 统计中。
15. **COFER 口径：** IMF 储备货币构成数据按季发布、滞后约一个季度、为全球总量层面数据，不用于短期市场择时。
16. **历史分位规则（对应原则 7）：** 分位数窗口必须固定并显式声明（如近 3 年/近 5 年）；窗口内若包含极端事件（如 2015 年股灾、2020 年疫情冲击），只标注"窗口内包含某极端事件及其时间区间"这一事实，不解释极端值对分位数值的作用方向（F17）。

具体口径约束（17–19，V2.5 新增）：

17. **操作数顺序：** difference/spread/ratio/percent_change 必须声明 operand_order；"剪刀差"定义为 M2 同比 − M1 同比。
18. **排名全集：** result_form=rank 必须声明 universe 与排序方向；全集变更视为口径变更——升 `caliber_version` 并重算历史，不得直接拼接。
19. **可比期起点：** 有口径断点的指标必须在指标注册表与每条记录上声明 comparable_from；跨断点的时间自比一律拒绝（填 caliber_mismatch），不得用"近似可比"放行。

### 6. 一致预期禁用（V2.3 原文照录）

平台不收集、不使用一致预期数据。理由：一致预期是把别人的判断引入平台，让平台承担了判断功能，违反"平台只枚举可能、判断归用户"的定位。不是因为数据不可得。

### 7. 历史事件统计禁用（V2.3 原文照录）

平台不做历史同类事件的统计拟合。理由：历史重复的是规律，不是具体事件；统计拟合的样本少、口径杂、不可复核，会让平台暗示"这次可能重复上次"，承担了判断功能。不是因为数据不可得。

### 8. 事实注册规则

同第六节。市场层类别骨架为六环（C1–C6，ADR-019）；板块层骨架见附录 F.2（同名同序六环 + R1–R3），**v1 不做个股层**（D10 关闭；将来要做须新开 ADR 与新骨架，不复用现有编号）。caliber_version 在指标注册表中声明，事实记录经 indicator_id 关联（见第六节事实注册规则）。

|---|---|---|---|---|---|

每个 Skill 必须写明以下六项，缺一不得交付：

1. **触发语例**：至少 3 条例句，覆盖参数省略与歧义情况。
2. **输入参数**：名称、类型、必填性、默认值、取值约束（如 window_days ≤ 90）。
3. **输出 schema**：指向第五节事实 schema / 附录 B 比价 schema / 8.1、8.2 事件 schema / 第九节六段模板，不重复定义字段。
4. **失败态**：数据不可得（填 missing_type + 给可替代项）、歧义（先问一个问题）、口径断点（拒绝自比）、锚不符（拒绝输出）四种情形的固定回应方式。
5. **禁止声明**：只写禁令编号（如"遵守 F03、F05、F06、F18"），不重抄条文，避免措辞漂移。
6. **产物位置**：Skill 文件路径、依赖的映射表与存储键（第十二节）。

层级 Skill 不得跨层判定（F07）；编排 Skill 不得新增或改写任何规则，只调用 Fact/Bijia/Event 三类 Skill 并按第九节模板拼装。

**full-workflow 的固定流程（ADR-029，编排不新增规则）：** ① 识别层与标的 → ② 判歧义（标的/窗口/口径/层级任一不明时先问一句）→ ③ 并行调用 facts（取数）、bijia（比价）、event（日历与分支）→ ④ 按第九节六段模板组装 → ⑤ 执行附录 D 的 V-清单（任一不过则拒输出）→ ⑥ 输出证据行版 + 固定尾句。层级 Skill（macro-layer / sector-layer）只决定“调哪几个”，不得绕过 ③–⑤。

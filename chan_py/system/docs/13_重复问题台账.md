# 重复问题台账（同一类问题不许修第三次）

规则：**同一类问题只要重复出现一次，就必须在这里登记一行**，并绑定一个"机械拦截"（测试/契约/守卫）。
没登记的重复 = 流程漏洞；登记了但没有拦截 = 空头承诺。

| # | 重复出现的问题 | 次数 | 现在的机械拦截 | 失败会怎样 |
|---|---|---|---|---|
| 1 | **卡片手写/改写**（格式又变、事件卡消失、缩略图不对） | 4 | 交付硬规则 + `check.py --card` + `selftest` 卡片哈希记录 | 契约不过；哈希不一致会被指出 |
| 2 | **单位混用**（亿/万亿/十亿美元混着算） | 3 | `units.py` 归一 + T32 + 金标复算 + 卡片序列量级断言 | 单元测试失败 |
| 3 | **同一数字两条路径**（facts vs history 不同） | 2 | T34 同日同值 + `daily_diff` 数值跳变 | 回归失败 |
| 4 | **判据静默消失**（缺行不报不可读） | 2 | T31 每环至少一条 + C3 长短端必须都在 + 跳过登记表 | 回归失败 |
| 5 | **数据过期仍出状态词**（板块停在 11-13、源停更） | 3 | 停更守卫 + 快照守卫 + 板块 C2 新鲜度断言 + `daily_diff` | 单元测试失败 |
| 6 | **布局两处各写一遍**（列宽 vs 容器宽） | 2 | `data/card_spec.json` 唯一来源 + [R1.7] 契约 + 格式指纹 | 契约/单元测试失败 |
| 7 | **事件与六环关系丢失** | 2 | `data/event_rings.json` + R8 环条 + 环条数/无红蓝断言 | 契约失败 |
| 8 | **文档与实现不同步**（SKILL 过时、数字对不上） | 3 | T29 三方一致 + 台账数断言 + 歧义扫描 | 回归失败 |
| 9 | **月度月份解析丢 1–9 月** | 1 | `history._dp_of` 六写法断言 | 单元测试失败 |

## 交付环节（唯一仍靠自觉的一条）

第 1 项的前半段（生成）已被机器守住，后半段（**贴在回答里**）无法用代码校验。
因此固定动作：

1. 出卡后**只允许原样粘贴** `reports/card-market.html` 与 `reports/card-events.html`；
2. `selftest` 会记录两卡的 sha256 到 `reports/card-hashes.json`——粘贴前后哈希一致即可自证没改过；
3. 一次回答里**两张都要贴**，缺一张即为违例。

## 判定"项目是否在退化"的三个数

| 指标 | 健康值 | 怎么看 |
|---|---|---|
| 同类问题重复次数 | **0** | 本台账；出现第二次即升级拦截强度 |
| 每次改动是否先有失败测试 | 100% | `test_units.py` / `test_regression.py` 条目数只增不减 |
| 当前拦截覆盖率 | 见 `selftest --deep` | 16 项 + 深度巡检 0 错误 |

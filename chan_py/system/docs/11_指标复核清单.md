## 二、冗余判定的边界（先把话说清）

**冗余是逻辑性质，可得性是经验性质。** 一个指标"逻辑上多余"，不等于"抓数时用不上"；反过来，一个指标"逻辑上必要"，也可能一张表都没有。所以本节不写"删除"，只分三类：

### 2.1 降为数据层（证据位取消，数据仍必须存）

判据：它由保留项**同源或派生**——同源意味着同生共死（有它就有主项），派生意味着随时能算回来。所以删的只是"证据位"，不删数据。

| 项 | 为什么降级 | 数据层怎么处理 |
|---|---|---|
| M2 余额（MKT_M2_BAL） | 同比已含其变化；余额是算同比的中间量 | 存 raw_series，供算同比 |
| M1 余额（MKT_M1_BAL） | 同上；且受口径断点影响 | 存 raw_series |
| 居民定期存款（MKT_HH_DEP_TERM） | 与总额同表同源，比例 = 定期 ÷ 总额 | 存字段；若源只给定期，总额另找或反算 |
| 板块成交占比（SECTOR_AMT_SHARE） | 与集中度同源；在板块层它是 C2 份额的登记项，**由 C6 派生、不独立采集** | 保留注册（板块层 C2），但不作为独立采集指标 |
| 融资余额增速（MKT_MARGIN_BAL_YOY） | 余额的 percent_change，比价层现算 | 无需单独存 |

### 2.2 改判保留（上一版我判错了）

| 项 | 上一版的错判 | 为什么改判 |
|---|---|---|
| **ETF 份额（INST_ETF_SHARE）** | 我曾说"留净申赎、份额降为替代源" | **顺序反了**：份额是交易所/基金公司**原始披露**，净申赎是"份额变动 × 净值"算出来的派生。若数据受限，先拿到的是份额，净申赎反而算不出来 |
| **证券客户保证金（MKT_MARGIN_DEP）** | 我曾说"无源，且被成交额/两融覆盖" | **信息不重叠**：它量的是场内存量自有现金（交易结算资金），两融量的是杠杆，成交额量的是流量。而且中国证券投资者保护基金有月度"交易结算资金余额"——我上一版只查了本环境的端点，没查官方月度表，这属于判断草率 |

### 2.3 不删（降为替代源或事件）

| 项 | 处理 | 理由 |
|---|---|---|
| Shibor 隔夜 / 7 天（`MKT_SHIBOR_ON` / `MKT_SHIBOR_7D`） | 降到 DR007 的替代源 | 共线，但 DR007 无源时它是第一顺位 |
| 政策动作（降准/降息，`POL_ACT`） | 不占事实位，进事件日历 | LPR/RRR 状态变化能看出动作；事件日历承载"何时发生" |
| QFII 持仓、关注度 | 标"后置" | 信息边际小，但是替代链上的备选，删了链就断 |

## 五、清单外的数据怎么办（这一节回答"名单是否封闭"）

**名单不是封闭集合，注册表才是。** 抓数时几乎一定会遇到"清单里没有、但确实有数据、而且能回答某个信息点"的东西。处理规则：

1. **不丢**：抓到了就登记，哪怕暂时没位置放。先写进"发现池"（可先用附录 C 的矩阵格式记一行）。
2. **登记要素**：layer、subject、channel、attribute/transform、value_kind、频率、口径断点、proves / does_not_prove。六环里哪一环缺证据，优先往哪补。
3. **登记即入环**：若它正好填了某空环，直接升为证据项（走事实注册规则，不临时造字段）。
4. **反向替换**：若清单内某项长期无源，而清单外某数据能回答同一信息点，就用清单外的替换原项，并在注册表记替代关系（不要因为"原清单这么写"而硬守）。
5. **不因清单而放弃**：本表出现过但漏列的指标（比如各类 ETF 申赎清单、港股通、股指期货基差、可转债、龙虎榜营业部明细），都属于"已想到但未登记"——它们没有出现在 36 个信息点里，不代表平台不使用。

> 一句话：**本表管"问题"，注册表管"数据"。** 问题清单可以缺，数据登记不能漏。

## 十七、分阶段实施计划

**两条原则（ADR-024）：**

1. **阶段只表达能力依赖，不表达指标重要性。** schema → 存储 → 渲染 → 校验 → 取数适配器，这个顺序不能乱；它跟"先接哪个指标"无关。
2. **指标的接入顺序由附录 C 的可得性决定，框架不排。** G1 先接、G2 采购后补、G3 留空并标注。全文不设优先级标签（ADR-024 已删除 P 级）。

**阶段与六环的关系：** 每个阶段负责"把一批可得证据接进链里"，而不是"完成一批指定指标"。第一阶段结束时六环里大概率有几环是空的——这是正常状态，按空环规则显式标注即可，不视为失败。

### 第零阶段：能力与可得性（1–2 天）

1. **数据源可得性矩阵（第一交付物）：** 按附录 C 模板逐项填写六环证据的取数路径、授权状态、频率、口径断点与缺失处置。
2. 按第十二节编写《环境适配清单》5 项（可用工具、渲染契约、数据源映射、存储方案、调度方案）。
3. 初始化指标注册表：indicator_id、channel、subject、attribute、transform、caliber_version、caliber_effective_period、comparable_from、value_kind、update_frequency、default_window。
4. 搭建存储骨架：事实注册表（含 revision_seq，初值 0 永不覆盖）、比价结果、raw_series、政策状态历史快照、事件日历快照与分支归档（键见 12.3）。
5. 验证渲染链路：一条比价数据 → 按 V1 判据渲染为折线 → 用户可见。
6. **官方事件日历可抓取性验证：** 抽查国家统计局发布日历、央行公告、交易所公告三个源；不可抓取的源记录 not_crawlable 并确定人工录入流程（8.1 的 entry_mode=manual 与链接要求）。
7. **北向口径验证：** 确认所选数据源在 2024-08 信披新规后的实际范围（盘后成交总额及总笔数、前十大活跃证券名单及成交额、季度持股），确认无"日度净流入"被当作官方数据混入。

完成标志：附录 C 逐项结论明确（G1 / G2 / G3）；适配清单成文；注册表可查询；存储可写入；比价折线链路可复现；三源可抓取性结论明确；北向数据范围结论明确。

**本阶段不做的事：** 不预先假设任何指标"应该有源"。某环零证据时，把结论写进附录 C，不在本阶段想办法补。

### 第一阶段：跑通一条链（1–3 天）

- 把附录 C 判为 **G1 的证据全部接入**（不是挑几个"重要的"），按六环落位；G2/G3 的环留空并标 missing_type。
- 至少做**一个时间自比 + 一个空间互比或排名**，验证比价能力。用什么指标取决于可得性：
  - 若 M2/M1 可得 → M2-M1 剪刀差（difference + percentile；operand_order = M2 同比 − M1 同比），窗口起点不早于 comparable_from（ADR-002）；
  - 若不可得 → 用当前可得的同类事实做时间自比（如成交额分位、涨停家数/涨跌家数的方向），**先验证比价能力，不锁定特定指标**。
- 接入至少一个宽基指数日线 OHLCV（raw_series，value_kind=price），仅作数据层存储，不参与本阶段比价、不渲染。
- 每条事实带齐 `subject / channel / proves / does_not_prove`；按六环顺序、六段模板输出。
- 配极简 bijia-measure Skill 与 fundamental-facts-market Skill。

完成标志：能按第九节六段模板输出事实层 + 对比层（+ 事件层如可用）；已接入的 G1 证据全部带四字段；六环里可拼的环有值、不可拼的环显式标注；V-清单全部通过；输出无判断结论、无价格序列形状的图。

### 第二阶段：补 G2（按采购进度，2–5 天/批）

- 每批数据源到位后，补对应环；同步更新附录 C 的档位与状态。
- 补全 bijia-measure 支持 spread + rank（rank 必带 universe）。
- **不设"必须补完某一清单"的完成标志**——补到哪算到哪，缺的继续留空。

完成标志：本批新到位的证据全部入链并完成对账；附录 C 状态同步；空环数量较上一版减少（量化即可，不要求清零）。

### 第三阶段：政策环人工化（1 天）

- C1 的政策状态与政策动作接入（人工录入为主）：每条须给 status_enum 与官方依据链接，entry_mode=manual；政策变化通过时间自比体现，不记录历史发布事件。
- C1 的"未来 30 天政策与发布日程"指针与事件层对齐。
- 验证 supersedes 只引用上一个状态记录，不展开为完整历史序列。

完成标志：C1 至少 3 条政策状态可追溯（含 effective_since、status_enum、官方链接、supersedes）；指针与事件层一致。

### 第四阶段：事件面最小闭环（2–3 天）

- 接入事件日历 schema（未来 30 天，市场层），含 event_status 三态流转、entry_mode 与快照保留（8.3）。
- 配 event-calendar Skill（接受 window_days 参数）。
- 配 event-scenario Skill 最小版本（只支持数据发布类"高于前值/低于前值/持平"三支，含持平判定与前值缺失时的排序不适用规则）。
- 验证：确定性标准（官方公告/官方日历明确列出）；取消与已发生事件的状态流转与保留；每日检查更新；整历重生成时保留上一版快照且 calendar_version 递增；手工录入条目必须带官方链接。
- 验证事件日历不标受影响指标。
- 验证事件分支 schema：分支、可观测标志、标志验证来源、受影响指标（必须是注册表中的 indicator_id）、prev_value（前值来源与可比性）、observation_time、calendar_version；无概率、无排序可能性、无方向判断、无一致预期、无历史统计、无回填字段。
- 验证分支默认排序规则生效（数据发布类按数值高低），以及前值不可得时 branch_ordering_applicable=false。
- 人工抽查**全部**已输出分支的 observable_flag 能否在官方源机械比对。

完成标志：对 2–3 个未来数据发布事件，能输出事件日历 + 分支列表；每个分支都有可机械比对标志与验证来源且人工可在官方源比对；排序按数值高低；无预测、无概率、无方向判断；快照可通过 get_calendar 复现。

### 第五阶段：板块层最小闭环（2–3 天）

- 前置条件：市场层宽基指数日线已就绪。
- 板块层按第六节的"同名同序六环"执行；开工前必须先落三条归属规则：**R1 成分表版本**（绑定行业分类标准 + 版本 + 生效日）、**R2 加总口径**（等权/市值加权、剔除停牌 ST、覆盖率下限）、**R3 跨版本处理**（禁拼接时间序列）。R1 未落地时，本阶段只能做截面，不做时间自比。
- 选 2–3 个行业 ETF，接入板块层事实 → 板块层比价 → 板块层事件日历（行业会议、政策发布、ETF 调整、板块财报披露日等，独立维护，不与市场层事件关联）。
- 板块层比价按 ADR-001 执行：ETF 对宽基指数只允许"收益率差"或"rank"，禁止价格水平比值与 base100 曲线。
- 板块 ETF 日线 OHLCV 仅在数据层存在，不渲染（F04）。

完成标志：至少 2 个行业 ETF 能按六段模板输出"事实—对比—事件情景"三层数据，且比价部分通过 V1/V2 判据；每个板块已绑定成分表版本（R1），加总项已声明覆盖率与口径（R2），跨版本时间序列被拦截并留下 caliber_mismatch 日志（R3），C4 默认空环并标 missing_type/不可读。

### 第六阶段：板块层扩展与层级 Skill 组合（2–3 天）

- 板块层事实扩展到第六节板块层清单的全部事实项（按附录 C 的可得性排序接入，可得者优先）。
- 板块层比价支持全部组合（含 percentile、rank，rank 必带 universe）。
- 编写 macro-layer、sector-layer 层级 Skill，组合为市场层与板块层的三层面板。

完成标志：市场层与板块层各自的三层面板可独立触发、可组合触发，输出无跨层判定；回归样本通过。

### 第七阶段：个股层（**v1 不做**）

用户已确认 **v1 不含个股层**（D10 关闭）。个股公告数据只在板块层作为加总原料使用，不另立一层。

完成标志：不适用——本阶段不执行；若将来要做，须新开 ADR 与新骨架。

### 第八阶段：总编排（流程稳定后）

编写 full-workflow 总编排 Skill；只串流程，不新增规则。

完成标志：端到端回归样本（输入 → 六段输出）可复现，且 V-清单（含 V-n）全部通过。

**止损条件：**

1. 某环在附录 C 判为 G3 且无替代 → 该环长期留空，**不得用近似量顶替**，也不得因此阻塞其他环（六环本来就是允许断的）。
2. 三个官方日历源均不可抓取 → 事件面降级为"人工录入 + 明示来源"，里程碑顺延。
3. 任一阶段超过本表上限 1.5 倍仍未达完成标志 → 停手复核范围，不靠延长工期硬推。
